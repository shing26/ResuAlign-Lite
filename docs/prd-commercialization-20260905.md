## 0. 决策前提：本文档推翻一条旧决策

`docs/plan-3.0-personal-copilot-mvp.md` 决策 #1 曾拍板：**「个人求职者自托管/单机工具，不做 SaaS 产品化」**。

本文档显式推翻该决策的 SaaS 排除部分，理由：

1. 原决策的语境是 2026-08 的单机验证期——当时产品连核心闭环都未验收，谈商业化为时过早。现在产品已有 840+501 测试基线、完整功能面和六轮 QA 记录，验证期使命已完成。
2. 「不做 SaaS」当时混入了两个判断：**不做全功能上云**（正确，应保留）和**不做任何收钱闭环**（过时，必须推翻）。没有收钱闭环，产品永远停在「自用工具」，无法验证任何商业假设。
3. 本文采用的商业形态是**混合制**：本地核心继续保留零上传、自托管的灵魂（不推翻原决策的精华），云端只做增值层（额度、同步、支付）。

同时沿用 `issue #62` 记录的三条定位红线（详见 §2.3），商业化**不改变**「不做什么」。

## 2. 市场与定位

### 2.1 产品已经有什么（商业化不是画饼，是包装已有能力）

以下能力**今天已存在**（依据：README、CONTEXT.md、已合并 PR #52–#66）：

- **快速评估**：粘贴 JD，30 秒内零 LLM 给出匹配分 + 前 3 条差距，先判断「值不值得投」。
- **对齐工作台**：逐条 diff 改写卡（新增/修改/删除 + 理由 + 置信度），逐卡采纳，A4 实时预览，导出 Markdown/PDF。
- **Provenance 防编造硬门**：每条改写必须溯源回母本简历，无出处的建议被拦截标记「建议复核」。**这是全市场最稀缺的信任卖点**——简历工具用户的头号恐惧是「AI 帮我编了假经历，面试时被打脸」。
- **投递复盘**：记录投递结果，产出「对齐版 vs 未对齐版」过筛率对比——给用户一个「这工具到底有没有用」的量化答案。
- **网申回填**：浏览器扩展读取本地档案，逐字段点击填充，数据零上传。
- **本地优先**：全部数据留在本机，这是隐私卖点，也是成本卖点。

### 2.2 竞品格局与空位

依据 `issue #62`（竞品借鉴取舍记录，2026-08-31）与 `docs/trend-research-report-2026-08-18.md`：

| 竞品 | 打法 | 它没解决的问题 |
|---|---|---|
| offerbiu、求职方舟 | 流程管理/聚合类工具 | 不碰简历内容本身，不解决「怎么改」 |
| jobfill（开源，23★） | 网申自动填表 | 要求用户手写 `resume-data.js`，档案不自动生成 |
| 各类 AI 简历优化 SaaS | 生成式改写，$20–50/月 | **普遍编造经历**，用户无法分辨哪些话是真写过的 |
| 猎头/简历代写服务 | 人工，数百到数千元 | 贵、慢、质量不稳定，且同样存在「代写与本人经历脱节」风险 |

**空位**：中文求职工具市场里，「逐条可溯源的 AI 对齐改写 + 投递效果复盘」没有直接竞品。ResuAlign 的差异化不是「改得更好」，而是「**改得让你敢签字**」。

### 2.3 定位红线（不做清单，承袭 issue #62，商业化为绝对护栏）

1. **不做自动海投**。与「local-first、用户主权」定位冲突，且有平台封禁与合规风险。卖点恰是「少投、精投」——对齐 5 个值得投的岗位，胜过海投 200 个。
2. **不做简历代写**。代写会摧毁 provenance 硬门，即摧毁产品灵魂。产品只重组、强调、修剪**用户自己写过的**事实。
3. **不做岗位信息聚合运营**。持续运营成本与单人项目不匹配，后端爬虫已退役（ADR-0028），不再回头。

红线之外的克制：商业化期间**不加**任何「AI 生成经历润色」话术，营销文案禁用「一键优化简历」这类暗示编造的表述。

## 3. 唯一 Persona 与付费场景

### 3.1 画像卡：陈骁，28 岁，后端工程师，骑驴找马

| 维度 | 内容 |
|---|---|
| 人口属性 | 26–34 岁，一线/新一线城市，1–8 年工作经验，本科及以上，技术/产品/运营职能均可（首发聚焦互联网技术岗）。 |
| 求职状态 | 在职，骑驴找马。**每次只同时盯 5–15 个岗位**，绝不海投（怕背调/怕内网传闲话），但每个岗位都想「投了就过筛」。 |
| 一天的时间线 | 通勤/午休刷 BOSS直聘、实习僧（校招期）、牛客；晚上 1–2 小时整简历——这是他最痛苦的一小时：改两句就怀疑「这么写 HR 真看得见吗」。 |
| 核心痛点 1：JD 匹配焦虑 | 明明经验对口，却不知道简历和 JD 差在哪。投出去的石沉大海（挂筛），没有反馈回路，不知道该改什么。 |
| 核心痛点 2：时间稀缺 | 在职求职，改简历的时间是偷来的。一份 JD 一个版本，手工对齐一份要 40–60 分钟，第 3 份就坚持不下去了。 |
| 核心痛点 3：信任危机 | 用过 AI 简历工具，被「帮我编了没做过的项目」坑过，面试被追问时下不来台。从此对所有生成式简历工具过敏。 |
| 现有替代方案 | ① 手工逐句对照 JD 改（慢、盲）；② 通用 AI 工具（快但会编，不敢用）；③ 找朋友/猎头改（欠人情/贵/不稳定）。 |
| 决策触发事件 | ① 连续挂筛 3 次以上，开始自我怀疑；② 看中心仪岗位，JD 里 3 个关键词简历完全没有；③ 猎头说「你这简历写得不行」。 |
| 价格敏感度 | 中高。月薪假设 15–40K，为一回合「拿到面试」愿意付一顿外卖钱（¥30–50）；为一次跳槽涨薪（+20%）愿意付一顿火锅钱（¥300 级）的年费。 |

**为什么是社招而不是校招**：校招学生量大但预算极低（¥0 是主流），且校招简历版式高度模板化、痛点在「不会写」而非「对不齐」；社招用户的痛恰好是本产品的「对齐 + 溯源 + 复盘」三件套。校招用户留作免费版自然溢出人群，不为其定制。

**唯一 Persona 原则的自我约束**：所有功能取舍、定价门槛、营销文案，都先问「陈骁会不会为此掏钱/会不会因此流失」。其他人群（校招、海外、HR）一律不作为设计输入。

### 3.2 付费场景：他什么时候愿意掏钱

付费设计原则：**先让他赢一次，再谈钱**。免费版必须完整跑通「对齐一份简历」的核心体验；付费点设在「他已上手、用量上升、想要更多」的位置。

| # | 付费场景（触发时刻） | 心理状态 | 对应 Paywall 位置 |
|---|---|---|---|
| S1 | 用免费额度对齐了 2–3 份简历，采纳率高，开始批量盯岗 | 「这东西真有用，但我这月要盯 15 个岗」 | 第 4 次完整对齐时弹「本月免费额度已用完」→ 专业版 |
| S2 | 一次用「批量对齐」处理了积压的待投岗位，看到对比矩阵 | 「如果能看到这些投出去的过筛率对比就完美了」 | 复盘页「对齐 vs 未对齐过筛对比」卡片点击展开时 → 专业版 |
| S3 | 网申表单填到第 3 个，开始嫌逐字段点击麻烦 | 「都到这了，能不能一键全填」 | 扩展侧边栏「一键全填」按钮 → 专业版（注：该能力属扩展期二，见 §6） |
| S4 | 新设备/换电脑，或不想折腾 API key | 「我只是想找个工作，不想学配 AI」 | 注册云端账号后的「免 key 模式」引导 → 专业版云额度 |
| S5 | 岗位库攒到第 21 个岗位，录入被拒 | 「我确实需要这个库」 | 岗位库达到免费上限（20 个）时 → 专业版 |
| S6 | 积压的待投岗位越攒越多，每周复盘都是手工逐个点开（2026-09-14 增，见 ADR-0038；能力兑现以 ADR-0037 实测结果为准） | 「我只想说一句『把这周新增的岗位都对齐，给我个排序』」 | 指挥台入口（Pro 专属，beta 期）→ 专业版 |

S1/S5 是**硬墙**（数量限制，到期必然撞上），S2/S3/S4/S6 是**软墙**（价值升级，体验驱动）。硬墙保转化率底线，软墙保口碑与升级叙事。

## 4. 定价策略

### 4.1 版本划分总表

| 能力 | 免费版（本地版） | 专业版（¥39/月 或 ¥299/年） |
|---|---|---|
| 快速评估（零成本规则打分） | **无限次** | 无限次 |
| 完整对齐（LLM 驱动） | **每月 3 次** | 无限 |
| 岗位库容量 | **20 个岗位** | 无限 |
| 简历中心（诊断/版本/网申档案） | 1 份母本简历 | 多份母本 + 无限版本历史 |
| 网申回填扩展（点击式逐字段） | ✅ | ✅ |
| 一键全填（扩展期二能力） | ❌ | ✅ |
| 批量对齐 + 对比矩阵 | ❌ | ✅ |
| 指挥台（AI 操作员：一句话批量对齐/晨报；永不代投、独立预算顶） | ❌ | ✅（beta，兑现以 ADR-0037 实测为准） |
| 投递复盘（对齐 vs 未对齐过筛对比） | 基础统计 | ✅ 对比归因 |
| LLM 供给方式 | 自带 key（BYOK，教程引导） | 免 key 云额度（含在订阅内，公平用量上限） |
| 数据同步 | 仅本地 | 多设备云同步 + 网申档案云备份 |
| 导出 | Markdown/PDF | Markdown/PDF/JSON |

标注加粗的三个限制（对齐次数、岗位库上限、单简历）是免费版的全部硬限制；**限制必须少而清晰**——每个多出来的限制条款都是落地页转化率上的文字税。

### 4.2 为什么是 ¥39/月 / ¥299/年

三个锚点交叉验证：

1. **市场锚**：行业报告记录同类 SaaS 定价惯例为 $20–50/月（`docs/trend-research-report-2026-08-18.md`）。¥39/月约 $5.5，远低于海外锚点，符合中国市场「订阅敏感、付费谨慎」的现实，是「明显划算」的定位。
2. **替代品锚**：简历代写一次 ¥200–800。年费 ¥299 < 一次代写，而 provenance 保证了「改的都是你自己的真话」——对被代写坑过的用户这是降维打击。
3. **心理锚**：一次跳槽涨薪按 20% 计，对本画像人群是数万元级年增益。¥299 占比 <1%，话术「**一顿火锅钱，换一次过筛率提升**」成立。月费 ¥39 卡在外卖×2 的心理档位，降低首月尝试门槛。

年费折扣（¥299 ≈ 6.4 折）的目的：把 12 个月的求职周期一次性锁定——本画像的求职周期通常 3–9 个月，年费保证他「跳槽成功后不用考虑续费，下次跳槽时它还在」。

### 4.3 免费版为什么敢「永久免费」

成本结构决定了免费承诺不会烧钱：

- **快速评估是纯规则计算**，零 LLM 调用，边际成本为零——它是最大的获客钩子，可以无限送。
- **免费对齐走 BYOK**：用户自带 API key，LLM 成本由用户直接承担，平台的边际成本≈0。产品内置的多节点管理（主备节点、健康检测、失败自动降级）本身就是「教你把 key 用明白」的增值体验。
- **专业版云额度**是唯一由平台承担 LLM 成本的入口，按订阅内公平用量上限控制（对齐一份简历实测冷启动 3 次调用、缓存重跑 2 次，单用户月成本可控在个位数元级）。定价含金量足以覆盖。

> 待验证假设（列入 §7）：云额度用户的实际平均用量。上线后按月校准公平用量上限，防止 1% 重度用户吃掉池子。

### 4.4 收款渠道的现实约束

单人项目、无企业主体的阶段（首发 6 个月内）：

- 主渠道：**支付宝当面付/微信收款 + 爱发电类赞助平台**发放订阅码，订阅码即 license，输入本地版或云端账号即激活。
- 规避项：暂不自建会员系统发票流程、暂不承诺企业采购（企业版是后续故事，不在本 PRD）。
- 升级路径：跑通首批 100 个付费用户后，再评估注册个体户/公司、接入正规订阅支付。**在验证付费意愿之前不建重支付基建**。

## 5. 用户旅程地图：从落地页到 Aha Moment

### 5.1 Aha Moment 定义

> **陈骁在工作台里第一次点下「采纳」，看着一张带溯源徽章的改写卡落进右侧 A4 预览，一句他自己写过的经验被重新措辞成 JD 的语言——全程没有一句他没说过的话。**

这个瞬间同时击中他的三大痛点：「原来差距在这」「原来只要一分钟」「它没有编造」。产品的激活事件（activation event）就定义为：**首次采纳 ≥3 张改写卡并保存终稿**。

### 5.2 完整旅程地图

| 阶段 | 用户行为 | 想法与情绪 | 产品接触点 | 流失风险 | 度量指标 |
|---|---|---|---|---|---|
| ① 认知 | 在牛客/小红书/V2EX 刷到「AI 简历工具又骗我，直到我用了这个每句话都能溯源的」类内容；或搜索「简历 匹配 JD」 | 「又来一个 AI 套壳？不过『不会编造』这个说法有点意思」 | 内容营销（挂筛复盘实验帖、对齐前后截图）、他人推荐 | 信任过敏：把本产品当成又一个编造工具划走 | 触达→落地页访问转化率 |
| ② 落地页 | 30 秒扫视：标题、溯源徽章演示 GIF、免费说明 | 「如果真不编造，我愿意试」 | 官网落地页：第一屏 = provenance 演示（一条改写高亮它的原文出处）；第二屏 = 三步流程；永久免费版说明 | 落地页讲功能不讲信任 → 跳出 | 落地页→下载/注册转化率 |
| ③ 获取 | 二选一路径：注册云端账号（轻，先见后装）或下载本地版（重，隐私优先者） | 「先别让我配什么 API key……」 | 注册即进 Web 试用；下载页给 Windows/Mac/Docker 三通道与一键启动脚本 | 本地版启动失败/环境问题直接流失 | 获取完成率、启动成功率 |
| ④ 首次价值（TTFV） | 引导流：粘贴一段 JD → **快速评估** 30 秒出分 + 3 条差距 | 「卧槽，它说我简历里根本没有 JD 要的『高并发』……说得对啊」 | 首访强制引导：预置一个 demo 岗位，一键快速评估，零配置零等待 | 关键脆弱点：引导流如果要求先传简历+配 key，流失率飙升。**必须先快速评估（零配置），后对齐** | TTFV（目标 <60 秒）、快速评估完成率 |
| ⑤ **Aha Moment** | 点进该岗位的对齐工作台 → 逐张看改写卡 → 采纳 3 张 → 看到终稿 A4 预览 → 保存 | 「这几句话全是我自己写过的，只是换了说法。**敢用了。**」 | 工作台：溯源徽章高亮、逐卡采纳、Live 预览 | 改写质量差/等待过久（冷启动 3 次调用的时长）→「还不如我自己改」 | **激活率（首日采纳 ≥3 卡并保存终稿）** |
| ⑥ 习惯养成 | 建岗位库、逐个对齐、投递后记录结果 | 「我已经离不开这个投递看板了」 | 岗位库看板、投递快照、截止提醒 | 对齐额度用完后无感降级 → 误以为产品坏了 | 7 日留存、周活跃对齐数（北极星） |
| ⑦ 付费转化 | 撞上 §3.2 五个付费场景之一 → 看到付费墙 → 扫码订阅 | 「3 份用完了，但第 4 份 JD 我真的很想投……」 | 付费墙文案必须**复述他刚获得的价值**（「你本月已对齐 3 份、采纳率 87%」），而非罗列功能 | 付费墙出现时机早于 Aha → 愤怒流失；价格犹豫 → 半月后回访 | 免费→付费转化率（目标假设 2–5%，待验证）、墙→支付成功率 |
| ⑧ 留存/推荐 | 跳槽成功（或没成功但对比数据在手）；在牛客发「这个工具让我看清了我和 JD 的差距」 | 「我推荐它不是因为好用，是因为它诚实」 | 复盘页的过筛率对比截图（自带传播性）、老带新：双方各得 1 个月专业版 | 求职结束即流失（这是产品节奏，不必抵抗——年费逻辑覆盖下一次跳槽） | 次月留存、推荐系数（K 因子）、年费续费率 |

### 5.3 旅程设计的三个关键决策

1. **快速评估放在体验最前端**：它是唯一零配置、零成本、30 秒出结果的触点，承担 TTFV 和「先赢一次」的职责。落地页 CTA 就是「粘贴 JD，30 秒看差距」，而不是「下载」。
2. **BYOK 不拦在门口**：免费版完整对齐需要用户自己配 key，这会把 80% 的非技术用户挡在 Aha 之前。对策：引导流内置「一键申请 DeepSeek key」教程 + 云端注册用户送首月体验额度，把 Aha 前置成本压到最低。
3. **付费墙永远在价值之后**：任何付费墙出现前，用户必须已完成至少 1 次完整对齐并采纳（激活事件）。这是硬性产品规则，写入验收标准。

## 6. 商业化改造增量清单（非技术语言）

按「复用现有 vs 需新建」标注，P0 = 首发必须，P1 = 首发后 1 个月，P2 = 验证后：

| 增量 | 说明 | 复用/新建 | 优先级 |
|---|---|---|---|

| 免费额度计量 | 「每月 3 次对齐」「岗位库 20 个」的计数与拦截。已有的每日 LLM 调用上限与超限拒绝机制就是配额墙的雏形 | **复用机制 + 新建商业配额规则** | P0 |
| 支付与订阅码 | 爱发电/收款码 → 发码 → 激活。首发不建自动支付系统 | **新建（轻量）** | P0 |
| 落地页 | §5.2 阶段②的官网单页 | **新建** | P0 |
| 付费墙 UI | 五个付费场景的拦截提示与升级引导 | **新建** | P0 |
| 云 LLM 额度（免 key 模式） | 专业版用户不配 key 直接用平台额度 | **新建**（成本模型见 §4.3） | P1 |
| 扩展「一键全填」完整版 | 下拉框/级联选择器支持（扩展期二，已有预研结论：高风险、需真实网申页采样） | **新建**（现有产品只到点击式逐字段填充） | P1（作为 S3 付费场景兑现） |
| 多设备云同步 | 网申档案与岗位库云端备份 | **新建** | P2 |

## 7. 风险与开放问题

| # | 风险/问题 | 应对 |
|---|---|---|
| R1 | **免费钩子校准**：每月 3 次可能太紧（扼杀习惯养成）或太松（无转化动力）。 | 上线首月 A/B：3 次 vs 5 次。观察指标不是转化率单值，而是「激活率 × 转化率」的乘积。 |
| R2 | **云额度滥用/防刷**：免费注册送体验额度可能被脚本刷。 | 体验额度仅限云端账号 + 手机号验证；额度计量复用现有配额墙机制。 |
| R3 | **单人客服压力**：BYOK 用户会遇到各种 key 报错（现有 L1 归因失真问题会放大成客诉）。 | 优先还清错误文案归因债（内部报告已诊断）；付费用户支持承诺控制在「工作日 24h 内」。 |
| R4 | **支付合规**：爱发电类渠道的稳定性和退款流程粗糙。 | 定位为「首发验证渠道」而非长期基建；跑通 100 单后升级正规支付。 |
| R5 | **竞品价格战**：若大厂出免费 AI 简历工具。 | 不在「生成质量」上接战，在「可溯源 + 本地隐私 + 复盘闭环」上防守——这三样需要价值取向，不是功能追赶。 |
| R6 | **传播素材合规**：营销内容使用用户简历截图需授权。 | 所有传播素材用合成案例（benchmark 目录已有 15 个合成用例可改编）。 |
| Q1 | 混合制下云端试用（Web）与本地版的功能对齐度：Web 试用版给到哪一层？ | 开放问题，建议首发 Web 试用 = 免费版能力，本地版 = 同等免费能力，避免双轨维护。 |
| Q2 | 「对齐 vs 未对齐过筛对比」数据量小的时候的说服力。 | 已有样本量守卫（样本过小只展示计数）；营销上需预设「n=10 以下不截图传播」纪律。 |
| Q3 | 年费用户求职结束后 6–11 个月的「空窗期」体验。 | 开放问题：空窗期内推送「岗位库体检」「简历年检」类轻内容，避免年费用户感觉「付了钱用不上」。 |
