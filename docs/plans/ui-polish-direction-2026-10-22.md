# ResuAlign 界面与体验打磨方向（2026-10-22）

> **一句话结论**：你现在的「无从下手」，不是因为功能不够，而是因为**每页都有 3 个以上同等重要的入口，没有任何一页告诉你「此刻最该做什么」**；再叠加一批「窄容器里中文被挤成竖排」的布局硬伤，于是每个页面都给人一种「还能用，但就是不对」的感觉。
>
> 这份文档 = 诊断（5 个系统性问题）+ 方向（5 条规则）+ 5 批可独立验收的施工单 + 明确不做什么。

## 1. 诊断：57 条问题，其实只有 5 个系统性问题

审计产出 57 条（驾驶舱/复盘/设置 20、岗位库/工作台 21、简历中心/全局壳 18），但去掉重复后，用户感知到的只有下面 5 件事。

### 1.1 版式没有主次：每个页面都是「页头 + 一排等权卡片」

- 驾驶舱：KPI 条 + 左侧 505px 大卡 + 右侧 411px 卡 → 左卡底部 135px 空白，因为行高由右列决定（`align-items: stretch`）。
- 复盘：主卡 438px 高、卡内 160px 空白；真正要处理的「超过 7 天无进展 1」被挤在右栏窄卡。
- 设置：简单模式整页 1 张 426px 卡 + 下方 340px 空白；顶栏承诺的「自动化规则 / 本地摄入 Token」在页内没有任何入口（唯一提示文案被 `isEdit` 条件吞掉）。
- 简历中心：页头 209px + 诊断卡 233px，正文从 y=898 开始（移动端整屏 844）——**正文过了一屏才出现**。

**本质**：卡片是「容器」，但页面没有「论点」。用户扫一眼得不到结论，只能逐块读，读完仍不知道下一步。

### 1.2 控件没有分级：每个局部都在同时提供 3–7 个主操作

- 简历页一屏 **23 个按钮**：诊断 3 个入口（`events.js` 在诊断完成后把「重新诊断」改名成「诊断简历」，于是同屏 3 个）、导出 5 个入口（3 个同权重）、「85 分」在页面出现 6 次、「删除」紧挨导出。
- 岗位卡单卡 **14 个可交互目标**、6+ 条重复入口；318 张卡 = 3,131 个 button + 325 个 select，键盘 Tab 走完约 4,452 站。其中「开始对齐」点一下**不确认就花一次 LLM 调用**，用的还是系统替你挑的简历。
- 工作台失败态有 **6 个触发 LLM 的入口**（顶栏重新运行、横幅换节点重试、设置面板重跑、3 张卡各「重试此条」），而失败原因是内容门禁——「换节点」大概率无效。
- `Ctrl+K` 是全局唯一入口，打开后**没有标题、没有命令列表**，只有一行「粘贴 JD 文本」提示。

**本质**：功能是按「能力」铺开的（每个能力一个按钮），不是按「用户此刻的任务」组织的。

### 1.3 容器没有收缩策略：「竖排字病」

同一个 CSS 反模式在 4 处复发：flex 行里文本项 `min-width:auto`（中文 min-content = 1 个字），其它固定宽控件把剩余空间吃到 0。

| 位置 | 改动前 | 现状 |
|---|---|---|
| 岗位卡标题 | 25px 宽 / 293px 高 / 每行 1 字 | 已修 |
| 工作台「目标岗位」 | 14.7×66 竖排 | 已修 |
| 移动端设置页头部 | 「LLM 已配置」3 行、简单/专家竖排、恢复默认 2 行 | 待修（S2） |
| 移动端工具条「排序」 | 18.5px 宽 / 36px 高 / 两行 | 待修（J8，10 分钟） |

**本质**：没有一条「任意文本容器必须能收缩并截断」的规则，所以每加一个控件就随机挤坏一处。

### 1.4 数据形态与数据分布脱钩：318 条真实数据，界面按演示数据设计

- 岗位库：看板固定 5 等分列，实际分布 **317 / 1 / 0 / 0 / 0** → 4 个空列白占 892.8px（76.7%），唯一有数据的列宽 223px、内容高 71,097px，**要滚 121 屏**。
- 更关键的是：318 条里 **209 条对齐失败、22 条已对齐、87 条待分析**，而「工作状态」在折叠态卡片上**一个字节都没有**（徽标全在默认 `display:none` 的 `.board-card__reveal` 里）→ 用户只能逐张点开 317 次才知道该处理谁。
- 三个 limit 各自拍脑袋：侧栏徽标 100（实际 318）、工作台切换器 200、看板 500（超 500 静默丢数据）。
- 转化条「投递转化 0%（1/318）」：有 1 条投递却显示 0%。

**本质**：所有页面都假设「数据少、状态都正常」；真实数据是「大量、压倒性地失败」。

### 1.5 状态不可见 / 失败被复制粘贴

- 工作台失败页：同一句「真实性评估判定本轮改写存在无依据内容」同屏 **6 次**，右栏 2 次还被 `nowrap+ellipsis` 截成一行；头部写「0 条改写建议」、主区却渲染 3 张 465px 大卡（都是「被拦截」）——互相打脸。
- 空态只有一种「还没有岗位」（筛选零结果时也这么说，用户会以为 318 条没了）；错误态是一块英文 `message` panel；加载只有「加载中...」。

**本质**：状态是「顺带渲染」出来的，没有「空 / 稀疏 / 失败 / 加载」四套模板。

### 1.6 工程层：CSS 是 append-only，改一处漏一处

`styles.css` 单文件 12,059 行 / 286KB：**1,616 个顶层规则块、296 个选择器被重复定义（多出 28.4% 覆盖块）、`.topbar` 16 块、`.app-shell` 12 块、24 个 `@layer components` 追加块、63 个 `@media` / 12 种断点**。移动壳有两套互相覆盖的实现（900px 两侧两个世界）；`.resume-doc` 两处定义把 h2 从 20px 压到 14px；token 251 个里 102 个零引用（`--btn-*`/`--field-*`/`--card-*` 整组空转）。

**本质**：token 层是设计过的（这是好消息，**不需要重建设计系统**），但组件层还在原地追加覆盖。你每次想改都「不知道改了会不会影响别处」——这就是「想改但没方向」的工程根因。

### 1.7 一个必须说清的产品层事实

318 条里 209 条对齐失败、22 条已对齐、**可用改写 0 条**（「已优化条目 0 条」），与 `docs/reports/app-self-use-post-165-2026-10-20.md` 的 3/9 succeeded、1/9 usable 一致。**这不是 UI 能修好的问题**（是 ADR-0059 P0 的产出可靠性问题），但它决定了 UI 的正确姿态：

> 界面不能假装「一切正常、快来看漂亮的建议」，而要诚实地说「这 209 条在门禁处失败了、原因是内容无依据、下一步是重跑还是换节点」。**先让失败可读，再谈好看。**

## 2. 方向：从「功能面板拼装」到「任务流工作台」

主线只有一句：**每页只回答一个问题，每屏只有一个主按钮；批量数据用列表，逐字阅读用文档；状态永远可见，失败只讲一次。**

### 2.1 六页的「一句话任务」

| 页面 | 要回答的问题 | 唯一主按钮 | 次区（最多 2 块） |
|---|---|---|---|
| 驾驶舱 | 今天先做哪一件？ | 继续工作台 | 最近动态、技能需求 |
| 岗位库 | 哪些要处理 / 哪些能投？ | 处理这一条（主操作 + ⋯） | 转化漏斗、筛选 |
| 工作台 | 这条改写能不能采纳？ | 采纳 / 重新运行（按状态） | JD 画像、差距、定稿 |
| 简历中心 | 这份简历能不能投？ | 诊断简历 | ATS 建议、版本 |
| 投递复盘 | 这周卡在哪里？ | 处理停滞项 | 节奏图、归因 |
| 系统设置 | AI 现在能用吗？ | 测试连通性 | 更多设置入口 |

### 2.2 五条设计规则（可直接照着改）

- **R1 一屏一主任务**：页头 = 标题 + 一句结论 + 一个主行动；主区只放这一件事；次要内容进侧栏或折叠。禁止「页头 + 一排等权卡片」。
- **R2 三档控件**：Primary 每屏 ≤ 1（实心强调色）；Secondary 用 outline；其余收进 `⋯` 菜单或展开区；危险动作 `danger` + 二次确认 + 说清影响范围。**触发 LLM 的动作一律先确认「用哪份简历 / 大概多久 / 会花多少」**。
- **R3 形态跟着数据走**：> 50 条 → 列表/表格（可排序、可筛选、有「共 N 条」）；看板只留给有流程含义的列，空列折叠成 56–72px 竖条；逐字阅读的内容（简历/JD/diff）→ 纸张式文档排版（15–16px / 1.55 行高 / ≤66ch 行长 / 真正的三级标题）。
- **R4 状态可见、失败只讲一次**：卡片折叠态必须能看出「待分析 / 已对齐 / 失败」；一个终态错误只出现在一个地方（横幅），其它位置只引用「见上方」。空/稀疏/失败/加载四套模板复用。
- **R5 不追加、先合并**：任何新样式改动前，先合并「同一选择器 ≥3 次」的重复块（优先 `.topbar` / `.app-rail` / `.btn` / `.panel` / `.card`），并给 `tests/frontend/css-structure.test.mjs` 加棘轮：重复声明数只减不增、断点集合不得扩大。

## 4. 现在不要做（否则又回到「想改但没方向」）

1. **不做整体换肤 / 重写框架**：token 层（字号 8 档、圆角 6 档、间距 11 档、语义色齐全）是好的，缺的是组件消费，不是新皮肤。
2. **不追逐微交互/动效**：`--shadow-none` 全线关闭、reduced-motion 有 4 份兜底，加动效只会让 CSS 更乱。
3. **不加新功能**（收藏、AI 面试、渠道统计…）：57 条里没有一条是「功能缺失」。
4. **不做移动端全量重做**：先修 W8 的 CSS 冲突（10 分钟）和 topbar（3h），再决定要不要底部导航（README 与实现不符，先改文档）。
5. **不把 UI 打磨当成 209 条失败的解药**：产出可靠性是 ADR-0059 的 P0，UI 只负责「让失败可读、让下一步明确」。
6. **不做领域目录分包**（R7 已暂停，见 AGENTS.md）。
