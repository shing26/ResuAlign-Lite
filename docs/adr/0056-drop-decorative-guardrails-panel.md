# ADR-0056: 删除设置页装饰性 Guardrails 面板，护栏数字改为后端真值

- **状态**: 已采纳
- **日期**: 2026-09-24
- **依据**: ADR-0042 决定 6e（逐项例外）；用户主动派单（「Guardrails
  有什么具体作用吗，没有的话应该做删除还优化激活这个模块」）
- **关系**: 只解冻本 ADR 列出的前端展示范围；不动后端护栏执行路径，不改探针
  判据与自用线阈值

## 背景：面板上的三个数字，两个是错的、一个是死的

设置页专家模式右侧的 `Guardrails` 面板（`data-guardrails-panel`）展示三行：

| 面板内容 | 真实情况 |
| --- | --- |
| 超时熔断 **40s** | **错**。实际是 per-role 超时：diagnose 45s、profiler 75s、gap_analyzer 60s、editor 90s、evaluator 60s，且可被 `RESUALIGN_ROLE_TIMEOUT_<ROLE>` 覆盖；`OpenAIClient.DEFAULT_TIMEOUT` 为 120s。40s 是更早设计留下的残值。 |
| 并发额度 **1** | 值对，但它是部署常量（`RESUALIGN_WORKER_CONCURRENCY`），不是用户在设置页能调的旋钮。 |
| 评估默认 ☑ | **死控件**。该 `<input type="checkbox" checked>` 没有 `name`、没有 handler、不读后端；真正生效的开关是它上方 `data-form="settings-eval-default"` 表单。两个控件长得一样、只有一个起作用，是典型的误导。 |

同时，面板本身不读任何接口——三行都是模板字符串写死的。它既不是状态展示，
也不是控制面。

**成本护栏是另一回事**：`api/services/cost_guard.py` 是真实执行路径（每日 cap
命中返回 429 `llm_daily_cap_reached`，同任务连续失败 3 次熔断
`repeated_failures`，成本按真实 token 估算落库）。但它的配置面板已在
2026-09-22 按用户要求从设置页删除，且 `Guardrails` 面板从来没有控制过它。

## 决定

**决定 1（删除装饰面板）**：移除 `data-guardrails-panel` 整块（含写死的
「超时熔断 40s」「并发额度 1」与死掉的「评估默认」勾选框）。同容器里的
「自动化规则」是真功能（有 `/api/automation/rules` 接口），保留，容器改为
`data-automation-panel`。

**决定 2（保留的展示必须是真值）**：Bento 概览里的超时卡改为读
`GET /api/settings/status` 新回传的 `worker_concurrency` 与 `role_timeouts`，
显示为「45–90 秒 / 按角色 · 并发: N」。前端不再保留任何写死的护栏数字，
只在状态请求返回前使用一份与后端默认值一致的 fallback（并注释来源）。

**决定 3（超时/并发不做成设置项）**：这两者是部署级参数，单机个人部署没有
调它们的场景；要调就走环境变量（`RESUALIGN_ROLE_TIMEOUT_<ROLE>`、
`RESUALIGN_WORKER_CONCURRENCY`）。本 ADR 不把它们做成 UI 开关——那只是把
装饰面板换成另一个没人用的旋钮。

**决定 4（成本护栏维持现状）**：后端执行路径与 2026-09-22 的删除决定不变。
需要设每日上限时走 `PUT /api/settings {daily_llm_cap}`；若将来要把上限做成
界面控件，应做成「可设上限 + 可看今日用量」的真控件，而不是恢复只读面板。

**决定 5（文案同步）**：导航描述与设置页副标题里的「Guardrails / 运行护栏」
措辞移除；简单模式里指向专家模式的说明改为「备用节点、角色分工与自动化规则」。

**决定 6（不做）**：不动后端护栏数值与执行路径；不删 CSS 里已失效的
`.guardrails-panel` / `.guardrail-box` 等规则（CSS 层归 ADR-0049/0050 的
重构序列，删除规则不在本次范围）；不新增 HTTP 路由。

## 后果

- 设置页不再展示与后端不符的超时数字，也不再有一个点了不生效的评估开关。
- 用户能看到的护栏数字（超时区间、并发）来自正在运行的进程，不会再漂移。
- 代价：设置页少了一处「一眼看到护栏」的位置；需要精确数值时看 Bento 卡或
  环境变量。

## 与既有 ADR 的关系

- **ADR-0042 决定 6e**：本 ADR 即该条的逐项例外记录（用户主动派单、消除
  误导性 UI），冻结令其余部分继续有效。
- **ADR-0053**：其范围是架构加固 §三，不含产品界面；两者不互相授权。
- **ADR-0055**：同一批用户派单里的岗位表自动同步，与本 ADR 无重叠。
