# ADR-0049: 解冻前端 CSS 架构重构并冻结 B0 基线

- **状态**: 已采纳
- **日期**: 2026-09-18
- **依据**: ADR-0042 决定 6f（阈值改动须新开 ADR 并回答「为什么现在改」）；
  ADR-0048 决定 9（6e 例外路线收口）；施工单
  `docs/plans/css-architecture-refactor-plan-2026-09-18.md`
- **关系**: 解除 ADR-0042 决定 6e 对 **B0/B1** 的冻结；不动探针线判据、
  不动自用线阈值、不放宽任何 6b/6c/6d 护栏

## 背景：为什么现在解冻

ADR-0042 决定 6e 把 app 冻结令作为自用线推进期的默认状态。ADR-0048 用逐项例外
修掉了三处直接挡路的布局缺陷后，例外的正当性来源已经耗尽——再往下都是架构
改造，不属于「让自用闭环好用」。

申请解冻的理由不是「规格写完了所以该施工」，而是下面三条可验证的事实：

1. **架构债已经开始产生实际错误。** 本轮连续三次遇到同一类病：`.app-rail` /
   `.topbar` / `.board-column` / `.board-card:hover` 都存在多份互相覆盖的定义，
   实测生效值与源码意图、与测试断言三方不一致。B0 修掉的
   `resume-center.test.mjs` 两条断言就是活证据——护栏常年绿灯，线上早已是另一套
   值。这类问题每修一处都要重新做一次级联取证，成本随文件增长而上升。
2. **后续改动会被同一病反复咬。** 只要 8 波覆盖补丁和 100 处 `!important`
   还在，任何新的 UI 调整都必须先证明「我改的是生效定义」，这正是 B1 要消除的
   成本，也是 ADR-0043 决定 2 的动机。
3. **B1 的收益与自用闭环直接相关。** 分层 + token 内联后，改版从「追生效定义」
   变成「改 token 值」，自用期快速迭代的边际成本显著下降。

风险控制：B0 先冻结可回滚基线；B1 单 commit 可 revert；每批验证不过即回滚，
不得进入下一批（施工单第 2 节纪律）。

## 决定

**决定 1（解冻范围）**：本轮只解冻 **B0 与 B1**。B2–B7 维持冻结，需在前一批
验证通过后另行引用本条推进。

**决定 2（判据不动）**：ADR-0041 决定 4 的探针线三档数值、ADR-0040 需求线 (a)
口径、ADR-0042 的双线与时钟定义**一字不改**。本次解冻不构成对探针结论的任何
暗示。

**决定 3（B0 基线，已完成）**：

| 项 | 结果 |
|---|---|
| 基线标签 | `pre-css-refactor`（指向解冻前 HEAD `a894a39`） |
| 后端全量 | **997 passed / 7 skipped**（276.50s） |
| 前端全量 | **489 passed / 0 failed** |
| 断言修正 | `resume-center.test.mjs` 的 `.board-column` / `.board-card:hover` 两条断言改为按级联取生效规则体，并断言 token 引用而非魔法数字 |

**决定 4（B1 边界）**：B1 = 加 8 层 `@layer` 声明 + 现有规则按块归层 +
`design-tokens.css` 内联进 `@layer tokens` + 迁移别名块临时启用 +
`!important` 归零（唯一豁免 `[hidden]`）。**同批一次完成**，理由是分层后
`!important` 的层间优先级是反的，分批会制造比现状更难 debug 的级联
（施工单第 2 节已论证）。

**决定 5（回滚）**：B1 必须保持单 commit，可整批 `git revert`；验证不通过即回滚，
不允许「带着失败继续下一批」。

## 验收（B1）

- DOM 度量探针（`.scratch/css_metrics_probe.py`，8 路由）与 B0 基线一致；
- 关键布局指标不回归：`.app-rail` = 224px、`.topbar` = 52px、`#job-board`
  在 1706 视口溢出 0、1024 视口列宽 ≥ 220px；
- `grep -c '!important'` = 1，且命中 `[hidden]` 白名单；
- `@layer` 声明唯一且顺序符合 ADR-0043 决定 1；
- 前端 489 passed、后端 997 passed / 7 skipped 不降；
- 5 个编码旧架构假设的测试按施工单第 6 节同步改写。

## 后果

- B1 是本次重构风险最高的一批：它同时改变层序、token 落点与优先级策略，
  不能只做静态检查就宣布通过，必须逐批跑 DOM 度量。
- `pre-css-refactor` 标签保留为回滚锚点；B1 完成后若出现视觉回归，
  优先整批 revert，而不是在新架构里继续打补丁。
- 探针线与自用线继续按 ADR-0042 独立推进，不受本次解冻影响。
