# 0059 — 双主线：app 自用验证优先，探针阈值不变

- **状态**: 已采纳
- **日期**: 2026-10-19
- **依据**: 2026-10-19 grilling 访谈；`data/jobs.db` 本地聚合；
  #115/#116 零产出归因与超时修复；用户对“架构自嗨 / 首次体验断层”的复盘
- **关系**: 取代 ADR-0041 决定 1（app 冻结新功能）与决定 7（托管 demo 押后）
  中与 app 自用验证冲突的部分；不修改 ADR-0041 决定 4/6/11、ADR-0042 的
  探针阈值/取证口径，也不改变自用线 JSONL 的既有定义

## 背景

2026-09-15 的 ADR-0041 判断：真瓶颈是“陌生人 30 秒跑通首次对齐”，因此
app 冻结、skill 探针升主线。该判断建立在“分发尚未开始”的前提上；截至
2026-10-19，探针线仍为 `dist_not_executed`（四渠道 outreach 0/4），自用线
为 1/3 合格例，两个前提都没有得到外部结果。

与此同时，本地真实租户 `local` 已累计 142 次对齐运行、4 次保存、5 条采纳；
最后一次集中运行（2026-10-09）为 123 runs / 0 saves。用户访谈确认：真正
让作者不愿意日常使用的首要原因是**产出可靠性**，不是首屏复杂度。2026-09
的零产出主因已由 #115/#116 定位为 profiler 超时预算不适配，并已合入
profiler 30→75、gap_analyzer 30→60 的修复；该修复仍需真实 JD 收敛验证。

用户同时确认：app 与探针应恢复为双主线；app 侧的大改不能立即替换默认
体验，必须先以真实自用结果证明价值。

## 决定

**1. 优先级明确降级**

- P0：真实产出可靠性验证。用 3 份真实 JD 在隔离实例跑当前模型节点，记录
  每例 `usable_diffs`、拒绝原因、阶段失败、耗时；通过线为每例至少 1 条可
  采纳建议并保存定稿，其中至少 2 例导出或记录投递。
- P1：ADR、术语与实施票落库；app 大改挂 feature flag。
- P2：三步工作台、用户文案映射、左右对比卡、真实性检查与输出体验。
- P3：内置 Mock 演示命名空间、BYOK 简化、首页空状态与本地漏斗指标。
- P4：导航命名、评分图形精简、Provider/节点/预算等展示型优化。

首页样例、导航爆改和模型配置面板不得插队到 P0/P1 之前。

**2. 双主线与冲突裁决**

app 与 skill 探针同为交付主线；探针的数值判据、取证方式、发布渠道和
`dist_not_executed` 事实保持不变。两线发生资源或合入冲突时，app 的真实
自用验证优先；探针不得被用来再次冻结 app，app 也不得冒充实测完成探针线。

**3. app 自用验证门槛**

app 新主线的验收单位是作者真实投递过的 JD。3 份不同 JD 均须至少采纳 1 条
建议并保存定稿，至少 2 份导出或记录投递。验证必须使用隔离数据目录，
不得写运行中的 8000 实例。若 3 份未过线，新工作台保持 feature flag 关闭，
默认回旧版，继续修可靠性；不扩大 IA 改造。

**4. 工作台形态**

新工作台采用固定三步：看差距 → 审改写 → 预览并导出。首步支持选已有
简历/岗位，也支持内联粘贴 JD、上传简历；真实材料在开始对齐时入库。
第二步使用左右对比卡；被真实性检查拦截的编造建议必须说明原因，并只在
原始经历存在可替代事实时给替代建议。第三步默认导出干净定稿，另提供带依据
版本；支持单条复制。三种改写风格按条按需生成，不批量预生成。

**5. 演示与用户语言**

内置演示使用确定性 Mock 模型和独立命名空间，可跨重启保留并一键重置；
演示产物允许导出，但必须带明确“演示”标记，不能进入真实岗位、投递或指标。
内部 API、代码和 ADR 继续使用 provenance / gate / diff；用户界面统一说
“真实性检查”“依据原文”“改写建议”，不暴露 Pipeline、Router、Provenance、
3-Gate 等内部术语。v1 不向用户暴露快/深模式。

**6. 配置与边界**

真实模型继续 BYOK，但简单模式压成“选服务商 → 粘贴 Key → 自动取模型 →
测试连接”；Base URL、备用节点、角色绑定留在专家模式。不提供托管试用
额度，不恢复服务端抓取，不做自动投递或简历代写。

## 后果

- ADR-0041 的 app 冻结令不再作为默认排期门；`frozen` 标签保留为历史记录，
  具体票必须重新分诊，不能继续把“冻结”当自动拒绝。
- 探针继续独立运行，但不再拥有阻止 app 验证的否决权。
- app 的 UI 重构先进入 feature flag 和原型验证，只有 3 份真实 JD 通过后
  才能成为默认体验。
- #114 的冻结总闸由本 ADR 取代；#72、#26 等旧票保留编号，但按本 ADR 的
  P2/P3 顺序重新分诊。
