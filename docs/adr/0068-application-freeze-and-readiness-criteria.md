# ADR-0068：秋招期打磨冻结与投递就绪判据

- 状态：已采纳（2026-10-31）
- 关联：ADR-0059（双主线）、ADR-0042（预注册时钟）、ADR-0067（投递主线）

## 背景

作者进入校招投递期（实习 + 秋招补录），待业，以秋招补录窗口为求职时钟。项目现状：
工程面（测试 / CI / 护栏 / ADR 治理）远超校招项目常规水位，但核心可用率未达标
（app 自用线 0/3；9 月真实对齐 4/5 零产出，guard 后复测 1–2/9 可用）。
「打磨到什么程度再投递」需要一条可判定的线，且不得与既有判据体系冲突。

## 决策

1. **投递不受项目判据门控**。投递自本 ADR 起持续进行；项目判据（ADR-0059
   自用线等）定义的是「能在面试里宣称什么」，不是「能不能投」。
2. **本 ADR 只设「打磨终止条件」，不改任何既有判据**。ADR-0042/0059 的阈值与
   取证口径原样保留；自用线验收只是时间上后移，数值不重谈。
3. **打磨范围只含三项**：① ≥3 份取证投递走完全流程；② 每份的采纳/跳过/手改
   记录沉淀为真实 eval 数据；③ 面试叙事与简历 bullet 定稿。演示材料、探针分发、
   新 feature、UI 优化一律不在范围内。
4. **取证投递**（术语见 CONTEXT.md）：重点公司投递走完整闭环（JD 入库 → 对齐 →
   采纳/跳过 → 保存定稿 → 记录投递）；海投走快速通道（Ctrl+K 零 LLM 预检），
   不计入取证。
5. **冻结判据 = 过程判据**：冻结日验收只看 ①②③ 是否完成，模型可用率不进判据，
   出多少记多少。理由：可用率不由作者控制，把不可控结果写进完成判据是 ADR-0042
   时钟失控的复刻条件。
6. **代码边界：只修阻断取证闭环的 bug**。取证中发现的非阻断问题只记录不修。
7. **冻结日期锚定外部事件**：以秋招补录窗口内最后一次补录投递日为准。护栏：
   若 2027-01-15 前未发生任何补录投递，视为已冻结——防止浮动时钟重演
   dist_not_executed。
8. **探针线挂起**：`dist_not_executed` 状态保持，处置推到春招后；本 ADR 不关闭它。

## 后果

- 冻结日后仓库 commit 归于静默是**预期行为**，不是弃坑；春招前做一次封版复盘。
- 若冻结日自用线仍未过线，面试叙事默认走「诚实失败数据 + 归因」版本（Tier B）；
  出现合格例则升级为「自用成功」版本（Tier A）。两个版本的口径都来自本仓记录，
  不临场编造。
- 简历与叙事只使用本仓可复现数字，不因结果好坏调整口径。

## 备选与不选

- **结果判据（≥1 完整合格例才算完成）**：能保证「宣称成功」，但卡在模型质量上
  会错过冻结日期；
- **ADR-0059 自用线全过才算完成**：最严，秋招窗口内大概率来不及；
- **具体冻结日期（2026-12-31）**：日期确定便于执行，但补录窗口结束日是外部事件，
  不可预知，故改为锚定事件 + 护栏日期。
