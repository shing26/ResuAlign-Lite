# 0054 — 评分短板实证加固：可复现实验、CI 门禁与分层冷启动

- **状态**: 已采纳
- **日期**: 2026-09-21
- **依据**: `D:/WorkBuddyData/ResuAlign-Lite-短板清单-20260921.md`
  与 `D:/WorkBuddyData/项目开发判断标准-三维度评分体系-20260920.md`
- **实施**: GitHub issue #129
- **关系**: 不改 ADR-0040/0041/0042 的探针判据、自用线阈值或冻结例外；
  本决定只增加工程实证与防退化守卫，不新增产品功能

## 背景

2026-09-20 的项目评估以 `36abe5a` 为基线，给出后端 71/81（87.65%）。
短板清单把 B9/B3/B6/B11 排为优先补齐项，B10 明确接受 2 分：

- B9 的问题不是测试少，而是 README 的 `840 + 501` 已过期，评估时看到的
  `100 文件 / 931 用例 / 85%` 又未经同一提交现场复核；
- B3 已有超时、角色回退、节点熔断和 watchdog，但没有降级触发与恢复的
  现场数字；
- B6 已有调用次数与模拟 wall-clock 门禁，但没有 P99 和并发→QPS 曲线；
- B11 已有 Dockerfile、compose 和双平台启动脚本，但没有冷启动耗时。

评分标准规定 3 分必须同时具备数字、可复现路径和防退化守卫。仅补一次人工
测量会在下一次改动后再次失效，因此本 ADR 把测量装置和 CI 门禁一起固化。

## 决定

**1. before 与正式环境**

- before 固定为 clean `main@0df6a18`。若 `main` 前进，先在原基线完成 before
  取证，再 rebase；不得把后续无关提交混入 before。
- GitHub Actions Ubuntu runner 是容量与冷启动的正式数字来源；本机 Windows
  结果只作交叉验证，必须与 CI 数字分表记录。

**2. B9：测试数字采用固定快照 + CI 为持续事实源**

- README 记录一次 clean 实测的 commit、日期、命令、后端 passed/skipped、
  覆盖率、前端/扩展 passed 数。
- README 明确声明：固定快照是历史证据，最新 JUnit/coverage CI artifact 才是
  持续事实源。
- 不增加脆弱的“每新增一个测试就同步改 README”文本一致性门禁；CI 的
  测试通过、覆盖率 85% 门禁和 artifact 上传继续承担防退化。

**3. B3：用本地故障注入证明熔断与恢复**

- 实验必须走真实 `OpenAIClient → role_router → LLMNodeStore` 调用链，
  不使用真实外部模型。
- 主节点指向持续返回 HTTP 503 的本地假上游，备用节点指向健康本地上游；
  每个 trial 建立独立数据库和上游。
- 连续调用直到主节点累计 3 次确定性失败后熔断；备用节点须接管，后续调用
  不得再命中禁用主节点；对恢复后的主节点做一次成功探测后，调用链必须重新
  使用主节点。
- 脚本默认执行 5 个 trial，任何一个不变量失败即非零退出，并进入 CI Stage 2。

**4. B6：容量曲线使用确定性 API 混合负载**

- 正式负载不调用真实 LLM。隔离 uvicorn 使用临时 `RESUALIGN_DATA_DIR`，
  请求组合固定为 50% `POST /api/quick-eval`、25% `GET /api/jobs`、
  25% `GET /health`。
- 并发档位为 `1,2,4,8,16,32`；若 32 仍未见拐点则扩展到 64。每档 200
  请求，重复 3 次取中位数。
- 输出总体和分端点 QPS、P50/P95/P99、错误数。拐点是 QPS 相对上一档增幅
  首次低于 20% 的并发档。
- CI 基线与当前运行比较：错误率必须为 0，同档 QPS 不得低于基线的 50%，
  P99 不得超过 `max(2×基线, 基线+100ms)`。基线只能通过显式
  `--update-baseline` 更新。

**5. B11：冷启动分层记录**

- 正式证据分三个数：原生进程 5 次冷启动的 p50/p95、`docker build --no-cache`
  的构建耗时、空数据卷容器启动到 `/health` 的时间。
- “冷”定义为新进程、新临时数据目录和空数据卷；不承诺清空操作系统文件
  缓存。
- 容器必须实际运行并验证 UID 1000 与 `/health`。
- 构建耗时只记录；原生 p95 与容器运行时延进入提交基线和 CI 回归门禁。

**6. B10 接受 2 分**

配置继续采用“钳制、绝不 raise”，不为评分改成启动期拒绝。保留 ADR 记录的
本地优先取舍，不新增 `/config/diagnostics` 端点。

**7. 不改变公共契约**

本决定不改 HTTP 路由、请求/响应 schema、OpenAPI、数据库迁移或用户可见
行为。只新增 benchmark CLI、JSON 结果契约、CI 步骤和文档。

## 后果

- 四项短板从“代码已写、没有数字”变成“命令可跑、数字可查、CI 可守”。
- CI 时间和复杂度增加：B3 为纯本地 HTTP 实验；B6 增加并发压测；B11 增加
  容器构建。三项在独立 job/step 中失败时可直接定位，不回滚彼此。
- 确定性 API 容量曲线不能替代真实 LLM 端到端延迟；真实模型质量继续由现有
  online benchmark 和产品探针衡量，边界在报告中显式注明。
- B10 的 2 分会继续降低总分；这是接受的设计取舍，不是遗漏。
