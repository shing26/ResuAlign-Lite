# 0042 — 预注册式重锚：探针判据时钟起点与「探针线 ∥ 自用线」双线拆分

Status: accepted (2026-09-16 07:22 签署，预注册；签署时刻早于任何非作者首跑数据的产生，见决定 5a)

## 背景（证据链，非估计）

1. **原时钟起点与理由**。ADR-0041 决定 4 把判据的 4 周时钟起点钉在
   「转公开时刻」（2026-09-15 14:16 UTC），并明写理由「宁可早停表」——
   当时的隐含前提是：**转公开当日即开始暴露**。
2. **前提被实测证伪**。发布包列明的两项人工动作至今未执行
   （`docs/probe-112-outreach-2026-09-15.md`「机器能做的都做了，剩两件
   要人点一下」）：置顶 first-run feedback discussion、四渠道 outreach。
3. **零曝光快照**（2026-09-16 03:56 GitHub API / GraphQL 实测）：
   `created 2026-09-15T14:16:06Z` / `pushed 2026-09-15T14:38:46Z`
   （此后无推送）/ **stars 0 / forks 0 / watchers 0** /
   `discussions.totalCount = 0`。即：发布 **17 小时后零曝光**。
4. **按本合同字面的后果推演**：零曝光 → 非作者首跑 0 例 → 0 < 2 →
   决定 4 判**证伪** → 决定 10 触发「skill 线冻结、回 app-only、
   不开第三条线」。而 app-only 的自身基线（59 租户中 58 个为测试流量、
   唯一真人租户中断于 08-17、`alignment_metrics` 全表 `accepted = 1`、
   ≥3 版简历 0 份）已经判过：**这条路没有外部需求**。
   即：不执行分发，等于按合同把主线降级到一条已被实测证否的路。
5. **问题定性：这是测量错误，不是方向错误。** 在「未暴露」状态下测量
   「暴露效果」，得到的是关于测量的结论而非关于需求的结论。测量学上
   正确做法是**让时钟与被测事件对齐**，而不是让被测事件去追时钟。
6. **本次修正的唯一合法形式 = 预注册**。决定 10 明令「触发条件白纸黑字，
   事后不许凭感觉谈判」。因此重锚必须满足三个条件，本 ADR 逐条满足：
   (i) 在任何非作者首跑数据产生**之前**签署；(ii) 改动方向事先声明、
   不许边看结果边改；(iii) 数值阈值**不放宽**，只修正时钟起点与线的划分。
   签署时刻 2026-09-16 07:22，此时非作者首跑数据 = **0 条**，无结果可循。

## 决定（7 项）

**1. 时钟起点 = 四渠道 outreach 全部发出当日。** 以作者当日追加到发布会话
的记录为准（精确到日），记为该日 work item。ADR-0041 决定 4 的「过 /
强信号 / 证伪」三档**数值一个字不改**，只改触发它们的时钟起点。

**2. 新增 `dist_not_executed`（分发未执行）语义。** 若 2026-09-23 24:00
仍未全部发出，判据登记为 `dist_not_executed`——此时**时钟不启动、判据保持
PENDING、观察窗不开启**。该状态**不是证伪**；其处置是「先执行分发，再谈判据」。
制度收益：「没发出去」与「发了没人要」从此可区分——这是本次修正最实质的一项。

**3. 判据拆为两条独立线**（各自取证、各自判定，不许互相顶替）：

| 线 | 口径 | 当前基线 |
|---|---|---|
| **探针线** | ADR-0041 决定 4 **原文**：非作者首跑 ≥5 例（各附门禁摘要行）或任意 1 例外部完整合格链 = 过；≥100★ 或社区二创 = 强信号；4 周后 <2 例 = 证伪 | 0 例（零曝光） |
| **自用线** | ADR-0040 需求线 (a) **原文**：合格例 ≥3（同一简历 ≥3 轮改→评→改 ∧ ≥1 轮采纳 ∧ ≥2 轮因果链），取证走验证器 JSONL | **1 例**（2026-09-15 狗食两跳链） |

**4. 项目级归档条件复合化。** ADR-0041 决定 10 原文两段，本次分别处置：

- 「证伪 → skill 线冻结、回 app-only、不开第三条线」：触发条件**不变**
  （探针线证伪即触发）。
- 「证伪 ∧ (a) 合格例 = 0 → README 挂 maintenance、全 Phase 冻结」：
  触发条件改为「**探针线证伪 ∧ 自用线 = 0**」。

即：**项目级终态需要两条线同时为负；单线失败只降级该线，不终结项目。**

**5. 形态判定三分支**（细化 ADR-0041 决定 9 的二分）：

| 结局 | 形态 |
|---|---|
| 探针线过 | 按 ADR-0041 决定 9：skill 升主线，app 降为可选持久层（只留看板 / 复盘 / 档案回填） |
| 探针线证伪 ∧ 自用线过 | **回 app-only，定位改为「作者自用工具」**；skill 保留为本地自用件（不发布、不运营、不再投分发）；冻结令解除范围仅限「让自用闭环好用」 |
| 探针线证伪 ∧ 自用线 = 0 | 按决定 10 全 Phase 冻结 + README maintenance |

**6. 护栏（硬；违反则本 ADR 作废，回到 ADR-0041 原合同）**

- **6a** 本 ADR 签署时刻必须早于任何非作者首跑数据的产生（本 ADR 头部已钉死日期）。
- **6b** 探针线的三档数值与取证形式（门禁摘要行**原样粘贴**）**不得修改**。
- **6c** 自用线每一例必须留下 JSONL 行（`round` / `trigger` / `chain` /
  `resume_sha256`）；口头复述、截图、`selftest.py` 合成剧本**一律不计**。
- **6d** 自用线输入必须是**作者真实投递过的岗位 JD**；
  `examples/demoflow` 一类的合成例不计入 (a)。
- **6e** 自用线推进期间 **app 冻结令继续有效**（本 ADR 不解冻任何新功能）。
  「让自用闭环好用」的改动须逐项引用本条走冻结令例外流程并留记录。
- **6f** 两线均不得中途重谈阈值。任何阈值改动须新开 ADR，且必须回答
  「**为什么现在改**」，而不是「结果不理想所以改」。

**7. 掉头期主线配比（本 ADR 一并裁决；性质为记录，非工程约束）**
ADR-0041 决定 1 的「探针 + 地基修复」两类工作，细化为三条并行轨道：

| 轨道 | 占比 | 判据 |
|---|---|---|
| 自用线：用作者 2027 届秋招真实投递跑 skill 四步闭环 | ~40% | 需求线 (a) 1 → 3 |
| 求职资产转化：把工程深度（provenance 门禁 / 漂移锁 / 四层验证方法 / 本次掉头裁决）转成可追问的面试证据 | ~40% | 能撑住 30 分钟技术追问 |
| 最小分发：执行探针发布包 outreach | ~15% | 探针线时钟启动 |
| **不做**：MCP / 通用 guardrail 下沉（ADR-0036 后置不变，探针出结果前不重开） | 0% | — |

地基修复 #115–#118 作为冻结令内的既有例外继续，不占上述占比。

## 后果

- 观察窗不再因「等待人工分发」而空烧；`dist_not_executed` 让「没发出去」
  与「发了没人要」在制度上可区分。
- 自用线获得与探针线同等的取证地位 → 需求线 (a) 成为**可单方面推进的线**，
  不再被动等外部分发。这是本次修正的主要收益，也是主要风险来源。
- **记录风险（必须留档）**：自用线天然只能证明「作者自己会用」，
  有把项目自我确证成个人工具的倾向。仅有的两道防线是护栏 6c/6d
  与探针线数值不变。若两线都过但探针线仅勉强达标，**形态判定仍以探针线为准**
  （决定 5 首行）。
- 已知盲区照旧（Jobscan / LoopCV / 超级简历 定价与留存未核实），
  不改变本判定。
