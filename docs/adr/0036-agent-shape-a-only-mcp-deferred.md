# 0036 — Agent 化只建「指挥台」（形态 A）；MCP 外部消费面无限期后置

Status: accepted (2026-09-14)

> 2026-09-15 注记（ADR-0041）：本 ADR 决策维持有效。skill 探针是需求
> 探针与分发渠道，不属于本 ADR 后置的「MCP 外部消费面」；B 复活判据
> 原样冻结，解冻时钟随 ADR-0041 探针判据走。

2026-08 的 agent 试点（原 ADR-0029，已删除）的死因不是「方向错了」：工具全挂在随后退役的爬虫上，且整个 agent 层是一条没有真实入口的并行第二路径。本轮改造方案（`D:/ResuAlign-Agent化改造方案-2026-09-13.md`）给出三种形态：A = 应用内指挥台（同进程 / 同 SQLite / 同队列，工作台旁多一个操作员席位，按钮路径一条不删）；B = 在 A 之上再暴露 MCP 外部消费面；C = 另起独立应用（已否决：绕开 `_queue_job` 的租户门/成本闸/watchdog 与契约门禁）。

**决定：只做 A，B 无限期后置。** 今天没有任何真实外部消费者需要把 Claude Desktop 直连本地求职引擎；这个「demo 特征」恰好复刻上次「入口不真」的死法，不允许出现在价值验证之前。Phase C 相应缩为「轨迹评测接 CI」，不与 MCP 捆绑。

## Consequences

- 从 git 历史恢复的 `mcp_server.py` 只作 tools.py 重写的参考，MCP 入口不做。
- 「B 是否复活」成为指挥台被真实使用验证后的显式决策点（非 Phase C 自动包含项）。
- ADR 编号不复用 0029：该号已被 `9e4139f` 删除且历史提交引用过它，重建同号会撞车；本轮决策从 0036 起新编。

## B 复活判据（Q5 — 未裁决，钉子先记）

- 计数口径候选：「20 条到达终态且含 ≥1 次人工审批的完整轨迹」（代理提出；口径与 N 值均待用户裁决）。
- **用户钉子（2026-09-14 访谈，Q4 轮顺带记录）**：触发条件里「真实外部消费者请求」必须硬定义——第三方 repo 的 issue、或别人的 MCP 客户端配置文档里出现了本项目的 server 条目，才算；群里有人说「想要」不算、用户自己想玩不算。定义不硬，第二条触发永远亮灯，B 就等于没后置。
