必要性审查（方案文档 §9.7–9.9）跑完 `data/jobs.db` 只读实测后推翻了原案的一条隐含前提：「Phase 0 过线 ⇒ 立刻建 Phase A」。本 ADR 记录门槛与分界，供裁决。

## 背景（实测，非估计）

- 真实人类使用只存在于租户 `local`：11 条 job，窗口 **2026-08-03 → 08-17**，此后中断；其中 4 条出 `final_draft`、2 条 `applied_at`。其余 51 个租户各 1 条 job、0 diff、0 定稿 = 自动化测试流量。
- **同一简历 ≥3 轮「改→评→再改」：0 例，从未发生。** `resume_versions` 98 份简历 = 92 份 1 版 + 6 份 2 版 + 0 份 ≥3 版。
- 唯一有采纳记录的口径 `alignment_metrics`（2026-09-05 起 52 行）里 `local`：runs 5 / saves 1 / diffs_total 9 / **accepted 1**。
- 五个招牌场景逐个检验：S1 挑高分（确定性 `match_scorer` 排序）、S2 归因（读已落盘的 `jd_profile_json`/`gap_report_json` 再解释）、S3 批量（`create_batch_align` → `job_ids` 数组 + 轮询模板）、S5 周复盘（`GET /api/dashboard`、`routers/review.py:103` 自陈「deterministic, zero LLM」）**都不需要执行期决策循环**；S4 定稿的关键是审批档而非编排。

## 决定（待裁）

**1. 编排两型的分界是「决策点」。**
预设流 (macro) = 服务端预先定好参数与顺序、一次调用跑完；决策点 (decision point) = 下一步取决于运行时观察、且该观察无法预先枚举成调用参数。**只有存在真决策点，显式 agent 循环才合法。** 判据可审计：某步若在 30 次重放里能被一条确定性规则复现同一选择，它就不是决策点。
因此 Phase A 的实现顺序改为：**先把 macro 层做厚（现成端点串成一次调用即可跑完的流程 + 一个自然语言入口路由），再按实测到的决策点决定是否上循环。**

**2. Phase A 开工需三线全亮，Phase 0 过线只点亮其中一条。**

| 线 | 内容 | 当前 |
| --- | --- | --- |
| 能力线 | Phase 0 过线（8 cell，协议 `f25a22f`）——只证明「当前模型能不能做」 | 待跑 |
| 地基线 | 真实对齐成功率回到可接受线；「零 diff 假成功」被 CI 锁死 | false（1/3 成功、9 diff 采纳 1） |
| 需求线 | (a) 同一简历 ≥3 轮改→评→再改 ≥ N 例；(b) 非测试租户周活 ≥ M 且连续 ≥4 周不中断 | false（a=0 例；`local` 中断于 08-17） |

需求线 (a)(b) 的形式与 N、M 取值由用户裁决；裁决前本 ADR 不算生效。原 §9.5 的「外部需求 = 0 所以 false」作废——那是把可测的一手证据混掉了，正确说法是**测到了、形状不对**。

**裁决记录（2026-09-14，需求线定稿）**：

- **(a) = Phase A 开工需求线，N=3 合格例**。合格例定义（三条全满足）：同一简历 ≥3 轮「改→评→改」 ∧ ≥1 轮有 diff 采纳 ∧ ≥2 轮的触发原因是上一轮评测结论（因果链条款——把「决策点」判据反向用在需求上；无因果的三轮手点不算，它会伪造循环需求）。狗食数据（租户 local）**计入合格**。
- **(b) = Phase B 门槛，非 Phase A 开工前置**。取值 M=1；租户定义收紧：周内有非只读动作（ingest/align/采纳）且非 CI/脚本自动化流量。理由：未上线时「非测试真人」无论域，按构造永假的开工门槛不是严格而是变相冻结；该谓词放到存在「别人」的段去亮（与 ADR-0038 的 B 触发条件同构）。**(b) 未被删除或降格，仅移动生效段。**

**3. 地基线修复与 Phase 0 / harness 并行，不排队。**
修 1/3 成功率与零 diff 假成功本来就是主叙事（对齐质量）自己的债，不因 agent 线是否开工而改变；串行只会让 Phase 0 的结论建立在一台已知会假成功的引擎上。

**地基线数值回写（2026-09-15，#110 归因报告产出，见
`docs/foundation-110-attribution-2026-09-15.md`）**：

> 地基线达标 = 连续 8 例真实对齐尝试中 `usable_diffs≥1` ≥7 例（≥87.5%），
> 且零代码级硬失败、超时类硬失败 ≤1 例。

分母三分解实测：硬失败 56%（91% 在 08-30 Phase E 前，已收敛）、静默降级
20%（qwen2.5:7b 批量 8 连跑各 1 diff——模型能力地板，不派单）、假成功
20%（9 月 muse-glimmer-30b 时代 succeeded+零产出，当前主症状）。
「1/3」为 9 月 run 级口径；尝试级有效产出率 5/41 ≈ 12%。
本线可自动计量的前提是 #111 的 `usable_diffs` 字段落地。

## 后果

- Phase 0 照跑（已封卷、已付费、产能力门槛与 M6 底账），但**不再自动放行 Phase A**。
- 若 Phase 0 结论是「模板化编排即可」（ADR-0037 预留的正式路径），叠加本 ADR 的场景检验，正确答案是 **macro 层 + 一个入口**，而非 agent 循环——这是省下整段 Phase A 预算的路径，不是失败。
- ADR-0038「Aha 验证做完再上 agent 有死结」的论证在本门槛下不再构成放行理由：需求线换成可数的 (a)(b) 之后，「验不了」不再等于「不必验」。
- 记录风险：需求线在**产品未上线**期间天然难亮；若因此把它写成「上线后再说」，本 ADR 就退化成原案。缓解 = (a) 项对内部/狗食数据同样成立（同一简历多轮改是作者自己就能造出的行为），(b) 项的 M 可以取 1。
