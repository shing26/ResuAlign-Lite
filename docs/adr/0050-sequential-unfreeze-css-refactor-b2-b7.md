# ADR-0050: 逐批解冻前端 CSS 重构 B2–B7

- **状态**: 已采纳
- **日期**: 2026-09-18
- **依据**: ADR-0049 决定 1（B2–B7 需在前一批验证通过后另行引用推进）；
  `docs/plans/css-architecture-refactor-plan-2026-09-18.md`
- **关系**: 解冻 B2–B7 的逐批施工；不改探针线判据、自用线阈值、
  ADR-0042 的 6b/6c/6d 护栏，也不新增产品功能

## 背景

ADR-0049 只解冻 B0/B1，并要求后续批次在前一批验证通过后继续。当前 B1 已完成：

- B1a `c3ac7af`：单层 canonical token 迁移与旧值原序重放；
- B1b `c86438a`：8 层归位与 `!important` 从 100 收敛到 1；
- 前端 `493 passed / 0 failed`，后端 `997 passed / 7 skipped`；
- B1a → B1b 的 8 路由 DOM 快照为 0 差异，reduced-motion / print
  计算样式一致；
- GitHub Actions `35330051867` 三阶段全部成功。

因此 B2 的前置条件已经满足。继续把 B2–B7 一次性解冻可以避免每批都重复
补一份治理 ADR，但必须保留原施工单的逐批回滚和验证纪律。

## 决定

**决定 1（逐批解冻）**：B2–B7 按施工单顺序解冻执行。每批开工前引用本 ADR；
不得跳批，不得把多个视觉维度并成一次不可回滚的提交。

**决定 2（B2 子批纪律）**：B2 的五个维度分别提交、分别验证、分别可 revert：

- ②a 字号收敛；
- ②b 间距归位；
- ②c 圆角收敛；
- ②d 阴影收敛；
- ②e z-index 收敛。

**决定 3（验收门禁）**：每批至少执行：

1. 相关前端测试与全量后端测试；
2. 构建 `node --check` / CSS 结构门禁；
3. 8 路由 DOM 度量探针无新增 console error；
4. 命中视觉变化时补明暗双主题截图目视；
5. 任一测试由绿转红、横向滚动回归、对比度失败或关键选择器丢失时，
   立即回滚该批，不带失败进入下一批。

**决定 4（边界）**：本解冻只授权 `styles.css`、前端模板与为验收所需的测试/
文档改动。仍不改后端、路由、`data-*` 契约，不引入构建工具，不引入
需要打包的运行时依赖。

**决定 5（B7 收口）**：B7 只有在 B2–B6 全部通过后才执行，删除迁移别名块并
落地 G1–G7 守卫；在 B7 之前，`--ra-*` 仅作为迁移期兼容层存在。

## 后果

- 前端重构恢复为一条可连续推进、仍然逐批可回滚的施工线。
- 每批的证据都留在提交、测试输出和 `.scratch` 验收入口中；不把“计划已写”
  当作完成。
- 若某批失败，只回滚该批；不得用回滚整条重构线作为跳过验证的替代。

## 与既有 ADR 的关系

- **ADR-0049**：本 ADR 沿用其解冻流程，只把作用范围从 B0/B1 扩展到 B2–B7。
- **ADR-0043/0044/0045/0046/0047**：仍是各批的架构与设计依据。
- **ADR-0042**：探针线和自用线判据保持不变；本 ADR 只处理已批准的 UI 架构施工。
