# ADR-0020: ResuAlign 2.0.1 redesign decisions

Status: accepted (2026-08-04)

## Context

2.0 已具备看板与三栏工作台骨架，但产品流仍是「管理后台 + 任务提交」：AI
结果默认不可见、投递记录要手动创建、岗位库不可拖拽、打开工作台存在空白
等待。2.0.1 的目标是把 ResuAlign 从「简历对齐工具」升级为「AI 求职决策
工作台」。跨部门联席会议（PM / UI / AI / Backend / QA）对现状做了只读
诊断，并对冲突点达成以下决议。

## Decisions

1. 看板采用五列 UI：心仪/待对齐、已生成对齐稿、已投递、面试中、Offer/归档。
   后端保留现有 canonical 状态并新增 `aligned`；`offer` 与 `withdrawn` 并入
   最后一列，用 `offer_at / rejected_at / notes` 区分。旧数据必须提供迁移
   映射，`applications` 表降为派生状态。
2. 一键导入走 preview 流程：URL / 文本 / 文件先进入
   `POST /api/jobs/preview`，LLM 结构化提取标题/公司/城市/薪资，用户只确认
   不填表；确认后入库并自动触发预分析。爬虫失败必须降级为文本确认，不阻塞
   用户。
3. 零点击预分析只跑低成本链路（classifier + JD profile + gap），按
   `(tenant, resume_hash, jd_hash, model, prompt_version)` 幂等去重并限制
   任务优先级；tailor 与 evaluator 仍由用户显式触发。
4. SSE 只作为事件通道，JSON 是唯一事实契约。事件类型固定为
   `job.stage / job.gap_ready / tailor.diff / job.result / job.error /
   heartbeat`；partial diff 必须标记 `tentative`，前端不得提前采纳；
   `job.result` 必须与 GET snapshot 完全一致。轮询保留为兜底。
5. Diff 引入稳定 `diff_id` 作为前后端主键；行内重写走
   `POST /api/jobs/{job_id}/workbench/rewrite`，instruction 白名单为
   `quantified / high_concurrency / concise`；禁止造数，禁止删事实证据。
6. API 新增 `routers/workspace.py` 与 `routers/kanban.py`；
   `GET /api/workspace/session/{job_id}` 是工作台默认入口，一次返回
   job/JD/resume/alignment/appraisal/crawl/meta.etag；读取绝不触发 LLM。
7. 异步爬虫使用持久化 `crawl_tasks` 状态机
   `queued -> fetching -> parsing -> classifying -> succeeded`，独立
   CrawlWorker 执行，重复 URL 幂等，写回 JD 前检查 `jd_text_updated_at`；
   不占用 LLM 分析 worker 队列。
8. 看板批量状态升级为公开 `/api/kanban/bulk-status`：单 SQLite 事务、逐行
   `updated/not_found/conflict`、乐观锁与幂等键，批次上限 200。
9. alignment 结果（score/gap/diffs/draft）必须持久化，不能依赖内存
   registry；batch/crawl 状态服务重启可恢复。
10. 契约测试改为增量模型：`contracts/openapi-v1.json` 不可变，新增路由/字段
    走增量 manifest；公开响应补 Pydantic `response_model`；破坏性变更升 v2
    并跨部门确认。
11. 前端继续无构建 Vanilla ESM；视觉改造在冻结的
    `#app / #toast-region / #print-root / data-* / aria-*` 契约内新增 Phase
    20 token。`backdrop-filter` 只用于 shell/topbar/命令面板/抽屉，`@supports`
    提供无 blur 降级；`#print-root` 必须全静态。
12. 三栏工作台仅高宽屏启用 `300px minmax(560px,1fr) 320px`；`<1280px` 右栏
    转抽屉，`<800px` 全部转 tab；保留 select/键盘作为看板状态迁移的
    无障碍兜底，Playwright 硬门不依赖拖拽时序。

## Consequences

- 工作台默认入口改为 session 聚合，前端初始 RTT 从 4+ 降为 1；增量更新由
  SSE/轻量轮询 + etag 承担。
- 零点击预分析必须受缓存、幂等、配额约束，避免把 LLM 成本放大到整个岗位库。
- SSE 认证不能使用原生 EventSource + Bearer header，前端用 fetch
  ReadableStream 或短时 cookie，禁止裸 query token。
- Playwright 断言最终状态与最终 DOM，不依赖 SSE 事件到达顺序。
- `contracts/`、OpenAPI response model、`#print-root`、selector 契约必须先
  于视觉重构修复，否则重构会在已破损的导出/契约基线上继续叠加。

## Deferred

- `fast_model / reasoning_model` 模型分层、在线 P95 nightly、60fps 采样、
  ContentStore 大文本外置与备份迁移，列为 2.0.1 的 P1 或后续版本。
