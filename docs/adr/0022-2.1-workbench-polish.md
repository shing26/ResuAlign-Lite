# ADR-0022: 2.1 Workbench Polish Decisions

Date: 2026-08-04

Status: Accepted

## Context

用户反馈工作台仍偏演示：JD 智能解析没有真实产出，对齐过程缺少即时反馈，
进入岗位必须从岗位库二次选择，切页后恢复不直观，设置页只有手动表单，
简历上传对表格/GBK 文本支持不足，部分招聘站抓取不到结构化字段。

## Decisions

1. **LLM 热切换**：在 `config.py` 增加进程内 `RUNTIME_LLM_OVERRIDE`，
   设置页保存 `llm_provider` / `llm_model` 后立即生效，不需要重启服务。
   API Key 仍只从 `.env` 或环境变量读取，不上报、不落库到前端可见字段。
2. **精简设置页**：前端移除“评估权重”和“薪资参照表”两个手动表单，
   保留运行状态、LLM 模型切换和分类词表。后端兼容字段继续保留，避免破坏旧数据。
3. **JD 智能分析**：新增 `POST /api/workbench/session/{session_id}/analyze`，
   复用现有 session pipeline 生成岗位画像与差距报告；打开工作台时若画像为空
   自动触发一次，失败后可手动重试。
4. **工作台岗位切换器**：工作台顶部提供岗位下拉，切换后直接进入对应岗位会话，
   不再需要退回岗位库；空工作台也提供岗位选择。
5. **切页任务保持**：后端 session 与 SSE 事件总线保留 30 分钟，回到工作台后
   重新挂接轮询并恢复对齐进度。
6. **简历解析**：docx 增加表格提取，txt 增加 GB18030 兜底，文本统一归一化，
   上传接口返回结构化 `sections`。
7. **爬虫准确度**：增强 JSON-LD / OpenGraph 元数据提取，清理招聘站公司名后缀，
   增加 SSR JSON（`__INITIAL_STATE__` / `__NUXT__` 等）兜底，飞书详情字段做 HTML 清理。

## Vocabulary

- `workstation session`：单岗位工作台的内存会话，包含 JD、简历、差距、对齐状态。
- `JD profile`：从 JD 提取的岗位画像（技能、职级、教育、场景）。
- `gap report`：简历与 JD 画像的差距分析结果。
- `align`：以主简历为基底生成逐条改写建议并允许采纳。

## Consequences

- 设置修改立即影响后续所有分析任务；已有进行中任务仍使用启动时的配置。
- 工作台打开会自动触发一次 JD 分析，真实 LLM 场景下会有一小段等待，
  UI 会显示“解析中”并提供进度与重试。
- 移除的表单仍可通过 API 修改，但不再向普通用户暴露。
