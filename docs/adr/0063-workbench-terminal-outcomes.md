# 0063 — 工作台终态分型与用户引导

- **状态**: 已采纳
- **日期**: 2026-10-20
- **关联**: issue #167、#166、#111、#159；ADR-0041 决定 5；ADR-0059

## 背景

ADR-0041 决定 5 把零可用产出分成「有缺口 = failed」和「无缺口 = succeeded」，
但仍以 `alignment_status` 和 `no_output:` 前缀承担全部终端语义。用户无法从
工作台区分「模型调用/结构化产出失败」与「简历没有足够原文依据，系统拒绝
编造」，岗位卡和 dashboard 还会把无缺口 succeeded 显示成「已对齐」。

## 决策

1. API 与持久化新增 `alignment_reason`，只允许三种公开值：
   `no_safe_rewrite`、`model_failed`、`no_gap`。旧行的 `no_output:` 仍保留在
   `last_alignment_error` 机读契约中，不进入原因列。
2. API 同时提供去除 `no_output:` 前缀的 `alignment_error`；用户界面只消费
   该清洁字段，不解析机读前缀。
3. `no_safe_rewrite` 为非绿色证据态，说明简历原文缺少依据及被拒绝的改写
   方向；有安全原句锚点的被拦截建议才提供单条重试。
4. `model_failed` 才显示重新运行对齐或更换模型节点引导。
5. 真无缺口显示「无需改写」，不显示「已对齐」，也不显示重跑引导。
6. 无可用 diff 时定稿与导出动作保持禁用，除非该岗位已有真实保存的定稿。

## 后果

- 本 ADR 限定性覆盖 ADR-0041 决定 5 中「无缺口文案必须带换模型重跑引导」
  的旧要求；`no_output:` 机读前缀和 `usable_diffs` 统计口径保持不变。
- 前端、dashboard 和岗位卡都按同一三态 taxonomy 渲染；模型失败与证据不足
  不再互相冒充。
