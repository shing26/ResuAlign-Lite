# ADR-0059: 冻结令例外 — 批量预分析可中止（#150）

- **状态**: 已采纳
- **日期**: 2026-10-04
- **依据**: ADR-0042 决定 6e（app 冻结期内「让自用闭环好用」的改动须逐项引用
  本条走例外流程并留记录）
- **关系**: 只解冻本条列出的范围；不改探针线/自用线判据、不改
  ADR-0042 的 6b/6c/6d 护栏，不解除 ADR-0041 决定 1 的功能票冻结

## 背景

「一键预分析」在批量运行时把按钮置灰，只显示 `预分析中 N/M`，没有任何
中止入口。实测吞吐 ~3.5s/岗位（每岗位两次串行 LLM 调用：`jd_profiler` +
`gap_analyzer`），120 个待分析岗位外推约 7 分钟，期间无法取消、无法关闭后停止、
无剩余时间预估（走查报告 Bug-06 / issue #150）。

这条落在冻结令内（属功能票，`frozen`），但维护者于 2026-10-04 明确指示
按 #150 → #152 → #153 顺序修复，本条据此走 6e 例外流程。

## 决定

1. `_preanalyze_batches` 增加 `stop: threading.Event`，批次循环顶部检查；
   已分析的结果保留，剩下的不再排队（最多多跑一个岗位）。
2. 新增 `POST /api/jobs/preanalyze-pending/{batch_id}/cancel`：批次不存在
   返回 404，已结束返回 409。
3. 状态响应新增 `canceled`，与每日额度早停的 `stopped` 区分开 —— 两者语义
   不同（用户主动中止 vs 定义性阻断），UI 话术也不同。
4. 前端按钮在运行中变为可点的停止入口。状态放模块级而非挂在按钮上
   （`data-action` 是 document 上冒泡分发），且任何时候都重新按选择器取
   当前在文档里的按钮 —— `render()`/导航会换掉节点。

## 契约

新端点属加性变更：`contracts/openapi-current.json` 与
`contracts/incremental/manifest.json` 同步登记，`contracts/openapi-v1.json`
不变（沿用 ADR-0055 决定 7 的程序）。

## 后果

- 7 分钟不可中止的等待变成可随时停止；已分析结果不回滚，剩余岗位保持待分析，
  下一轮 sweep 继续。
- 每日额度护栏的执行路径不受影响：`preanalyze_job` 内部的
  `enforce_daily_llm_cap` 仍会抛 `PreanalyzeUnavailable` 让整批 `stopped=true`
  早停，与用户取消互不干扰。
- #152（`#/today` 死路由）与 #153（移动端导航溢出）不属功能票，是缺陷修复，
  不需要本条例外。
