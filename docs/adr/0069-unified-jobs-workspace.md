# ADR-0069：职位大厅与投递看板合并为单一职位页

- 状态：已采纳（2026-11-19）
- 关联：ADR-0059（app 自用优先）、ADR-0065（按简历推荐）、#168

## 背景

`#/jobs`（旧岗位库/看板）与 `#/job-hall`（职位大厅）长期并存，两个入口
读同一份 `library_jobs`，却各自维护筛选、排序、空态和工具栏。用户要发现
岗位时走大厅，要推进投递时走看板，来回切换后筛选条件丢失，导航也出现
「职位」与「职位大厅」两个近义入口。继续维护两套页面只会让交互和术语
继续漂移。

## 决策

1. **单一规范路由 `#/jobs`**。`#/job-hall` 只做重定向别名，重定向时保留
   `job` / `view` 参数；不保留隐藏旧页或 `?legacy=1`。
2. **一个页面、两个视图**：默认「职位大厅」（列表 + 详情），可切到「投递
   看板」。列表/看板共享同一套筛选、排序与工作状态条件。
3. **视图记忆**：首次进入为列表；之后记住上次视图（`localStorage`）。
   显式 `?view=board|list` 优先于记忆值。
4. **深链**：`#/jobs?job=<id>` 打开详情，可与 `view` / `sort` / `status` /
   `search` 等参数组合；首次请求把服务端支持的筛选带入 API，客户端专属
   条件（招聘类型、薪资、匹配分、收藏、更新时间、工作状态）在内存过滤。
5. **详情布局**：宽屏列表为三栏（筛选 / 列表 / 详情）；看板使用抽屉。
   窄屏统一为抽屉或全屏，不挤压列表。
6. **主 CTA 随阶段变化**：未投递「开始对齐」；已投递/面试中「继续优化」；
   Offer/放弃「查看定稿」。状态流转规则不变：前向直接、回退确认、
   Offer/放弃收口确认。对齐终态优先于投递阶段：模型失败显示原因并提供
   「重新对齐」，无安全改写提供「查看证据」，无缺口提供「查看说明」。
7. **术语**：导航入口「职位」；列表「职位大厅」；看板「投递看板」；
   集合「职位库」；单条仍称「岗位」。
8. **旧渲染器退场**：`kanban.js` 只保留共享交互（渲染 hook、按简历推荐、
   看板拖拽），不再保留第二套 `renderKanban` 页面。
9. **详情历史可后退**：从列表/看板打开详情时写入一条历史记录；浏览器
   后退只关闭详情并复用已加载的职位数据，不重建页面、不重拉 `/api/jobs`。
   直接深链进入时关闭详情只纠正 URL，不把用户退出站点。

## 后果

- 用户在一个页面完成「发现 → 筛选 → 看详情 → 去对齐 → 记投递 → 看板推进」；
- 旧 `#/job-hall` 书签仍可用，但只会看到 `#/jobs`；
- 筛选与视图状态不再因切换入口而丢失；
- 前端测试从「两个页面各自契约」收敛为「一个页面 + 共享筛选/深链」；
- 后端、schema、API 契约不变，本次不引入迁移。

## 备选与不选

- **保留双入口、共享组件**：导航仍有近义入口，用户仍需判断「去哪个」；
- **只保留看板**：发现岗位时列表信息密度更高，看板不适合浏览大量 JD；
- **把大厅做成独立应用**：会重复导航、认证、词表和岗位数据读取，违背
  现有 `static/app` 单页体系。

## 验证

- 前端全量：`node --test tests/frontend/*.test.mjs tests/frontend/dom/*.test.mjs`；
- 路由：`#/jobs`、`#/jobs?job=`、`#/jobs?view=board`、`#/job-hall` 重定向；
- 交互：共享筛选、详情 CTA、收藏、重新评分、批量状态、看板拖拽；
- 状态可见性：工作状态筛选选中态、列表失败徽标、详情失败原因与动作；
- 响应式：1440 / 1200 / 1024 / 900 / 768 / 390 / 320 无横向溢出、控制台
  0 error；
- 真实流程：1 份真实 JD 走完「添加 → 筛选 → 详情 → 对齐 → 标记已投递 →
  看板移动」。
