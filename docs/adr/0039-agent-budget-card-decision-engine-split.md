# 0039 — agent 预算卡：决策/引擎分池、两道锁、两行报价、零自动语义

Status: accepted (2026-09-14)

一条 agent 指令 ≈ 20–35 次 LLM 调用（循环决策 ~6–15 + 派生引擎 15–20），而 `daily_llm_cap` 按「一次对齐 2–4 次」设计。Q3 访谈定下预算卡，本 ADR 落最终口径（含用户 2026-09-14 裁决的两道锁与两条归因）。

## 决定

**1. 归因口径：只数决策调用，引擎调用永不进 agent 桶。**
agent 的全部特权是「按你的按钮」——按钮花谁的池子，agent 按的就花谁的池子。引擎调用照走任务入口闸（`cost_guard.enforce_llm_task_entry` 原子预留 / 租户门 / watchdog / #103 连败熔断），与手点同口径、同一天花板。agent 桶守卫的是按钮不产生的唯一新成本面：循环决策调用。这是红线 1（agent 只能经工具面行动）的账本化：agent 的引擎消耗被**证明**永不超过用户亲自点按钮能烧掉的量。
否决的替代方案：引擎调用计入 agent 桶。该口径并非不可自洽（预留发生在 enqueue、撞帽只拦新排队、不杀已预留的在飞 job），放弃理由是双账本语义复杂 + 按钮对等原则 + `daily_llm_cap` 本已守卫引擎侧。

**2. 锁 1 · 预留制。**
决策调用不过 `_queue_job`，而总闸检查只发生在任务入口——因此轨迹起点必须对 agent 桶做**原子预留、finally 退还未消费**（`cost_guard.py:65` P1-1 同款「检查+预留一次原子条件递增」；`jobs.py:691` `llm_slot_reserved` 先例）。没有这道锁，双层帽套得再对，决策调用也从 cap 缝里整条漏走。实现警示：不得在工具调用路径再加一层 route 级预留（`cost_guard.py:52` double-book 教训）。

**3. 锁 2 · 帽值标定，招牌不撞帽。**
帽值不许拍脑袋：以 §6 五场景（本周岗位挑高分 / 为何分低 / 批量对齐 / 定稿 / 周复盘）**全部不撞帽跑通**为尺；分池后标定单位 = 「每场景决策调用数」。规则：单轨迹帽 ≥ 2 × max(五场景决策数)（向上取整），agent 日帽 ≥ 4 × 单轨迹帽。**数字在 Phase 0 落表**：30 题多步决策模拟即产出各场景真实决策计数，回填本 ADR 附录（联动 ADR-0037 / Q4 预注册）。

**4. 报价卡 = 两行报价。**
决策 ~N₁ 次（agent 预算 X/Y 剩余——**硬顶只罩这一行**）＋ 引擎 ~N₂ 次（与按钮路径共享 daily 池剩 X——报的是「别人家账本的行情」，不是自己桶的死刑；撞顶 = `cost_guard` 既有 429，session 如实呈现「队列说今天到顶了」）。两行数字都须算术派生（步数 × 工具档位），不许模型口算。

**5. 零自动语义。**
「明早继续」整条删除。撞顶后唯一续法是人主动说「继续」，且其语义 = **剩余写动作直接落入确定性队列**（等价手点排队：零决策调用、只花引擎池），界面明说「以下是不动脑的排队执行」——这一站同时兑现红线 6（降级可见）。次日续跑 = 一条新指令，重新报价。

## Consequences

- agent 桶是新增计数器（轨迹级预留 + 步界结算 + 退还），`daily_llm_cap` 语义零改动、不背新总闸。
- `budget_exceeded` 事件 payload 含两行报价回显与余量，前端如实渲染；审批档与报价门互不替代（报价=事前知情，审批=事后生效）。
- Q4 预注册必须包含「到顶即停」与「步界收尾」的决策调用语义测试（两协议臂都测），帽值标定表随 Phase 0 一并回填。
