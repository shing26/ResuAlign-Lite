# upcv-clawjob 仓库拆解报告（2026-08-21）

> 拆解对象：https://github.com/HireTechUpUp/upcv-clawjob
> 用途：为 ResuAlign 求职工作台改造提供模块 / 设计模板 / 优点参考
> 结论先行：该仓库**不是传统代码应用，而是 6 个 AI Skill（Claude Code 提示词层产品）**。
> 它的可迁移资产集中在 **SOP 编排、提示词红线、文档模板、模块闭环**，而非工程实现。

---

## 1. 仓库本质与架构

```
Clawjob (upcv-clawjob)
├── SKILL.md            # 总入口：功能总览 + 触发词 + 工作流导航
├── resume-create/      # 从零创建简历（身份识别→模块规划→逐步收集）
├── resume-edit/        # 编辑 / JD 对照改写 / 5 维诊断 / 导出 PDF
├── campus-search/      # 校招/实习项目搜索（项目级）
├── job-search/         # 岗位 JD 搜索（社招/校招/实习）
├── job-monitor/        # 每日定时监控 + 每日简报
└── auto-apply/         # 智能投递（ATS 识别 + 表单指导 + 经验复用）
```

三层架构：**Skill 提示词层（本仓库）→ MCP Server 工具层（resume.* / campus.*）→ UP 简历平台数据层**。
ResuAlign 的对应关系：Skill 层 ≈ 前端向导/工作流编排（你的 UI + API router），MCP 工具层 ≈ 你的 `api/services/*` + `engine.py` 流水线，平台数据层 ≈ 你的本地 store + job library。

## 2. 六个模块拆解

| 模块 | 职责 | 核心流程 | 关键资产 |
|------|------|---------|---------|
| resume-create | 从零建简历 | 前置检查 → 身份识别 → 模块规划 → 选模板 → 创建 → 逐步收集（STAR+HTML）→ 完成引导 | 身份分类、模块规划表、标题命名规范、写作红线 |
| resume-edit | 编辑已有简历 | 快速编辑 / 改写模式 / 诊断模式 / 样式 / 导出 | 细粒度工具集、改写协议、5 维诊断框架、HTML 格式规范 |
| campus-search | 校招项目搜索 | 意图提取 → searchRecruitments → 详情 → 引导下一步 | 筛选参数速查（CAMPUS/INTERNSHIP、批次、行业、公司类型） |
| job-search | 岗位 JD 搜索 | 意图提取 → searchJobs → getJob → 引导下一步 | 自然语言→筛选条件解析、结果表格、投递链接必带 |
| job-monitor | 每日监控 | 收集条件 → 立即预览 → 生成脚本+定时任务 → 每日简报 | 简报模板、launchd/cron 模板、管理命令（查看/停） |
| auto-apply | 智能投递 | 准备数据 → 识别 ATS → 复用/探索表单 → 记录经验 | ATS 域名识别表、ats-records 记录模板、敏感字段不代填 |

## 3. 值得参考的设计模板（可直接迁移）

### T1 — Skill / SOP 文档模板
每份文档统一骨架，结构本身就是产品：
```
frontmatter(name/description/触发词)
→ 前置条件 → 适用场景 + 不适用 → 工作流程（分步编号）
→ 参数速查表 → 示例对话 → 错误处理表 → 注意事项 → 相关 Skills
```
> 建议：ResuAlign 的 `docs/` 可以按此骨架为每个工作流补「操作手册」，
> 特别是「错误处理表」——目前 ResuAlign 的错误多散落在代码，没有面向用户的错误→动作映射。

### T2 — 简历创建向导（身份识别 → 模块规划）
按身份类型给不同的板块顺序，这是「从零创建」的关键差异化：

| 身份 | 板块顺序 |
|------|---------|
| 在校学生 | 教育 → 实习 → 项目 → 技能 → 荣誉 → 校园活动 |
| 应届毕业生 | 教育 → 实习/工作 → 项目 → 技能 |
| 职场人士 | 个人总结 → 工作经历 → 项目 → 教育 → 技能 → 证书 |

标题命名规范：`目标职位-姓名-经验`（例：`前端工程师-张三-3年`、`Java后端-王五-2年-北京`）。

### T3 — 简历写作规范（STAR + HTML + 红线）
- 格式：`<ul><li>` 结构，`<strong>` 强调量化结果，每段经历 3-5 条；强动词开头（主导/优化/负责/实现/推动/搭建/设计）；自然融入 STAR 逻辑但**不出现 S/T/A/R 标签**。
- 红线（比 ResuAlign 现在更细）：
  1. 职责匹配身份（实习生不写成项目负责人）
  2. 优化表达但不改变事实
  3. 数据不强行堆砌，没有数据就不编
  4. 需要推断数据时保守估算，宁可低估
  5. 用户没说的经历绝不添加

> ResuAlign 的 tailor.py 已有「Rewrite in STAR order: strong action verb + technical method…」，
> 但缺上述 4/5 条「保守推断、不添加」类约束，红线应抽成共享 prompt 片段供 diagnose/tailor/evaluator 复用。

### T4 — 5 维诊断框架
ResuAlign 现状：单分数 + 技能 + 问题 + 建议（一维输出）。
参考仓库的 5 维诊断可作为升级框架：
1. **完整性**：缺关键板块？内容充实度？
2. **匹配度**：（有目标 JD 时）关键词匹配程度
3. **表达质量**：是否具体、有数据、有动词？有无空泛描述？
4. **格式规范**：时间格式一致？排序合理？
5. **身份匹配**：描述与身份相符？（实习生不应写"带领团队"）

升级要点：各维分项 → 按优先级给建议 → 询问是否逐项执行（可复用现有 Diff 采纳机制）。

### T5 — JD 对照改写协议
ResuAlign 已有逐条 Diff 采纳，参考仓库补了**方向层确认**，值得补充：
```
确认目标职位/JD → 给出 2-3 个改写方向（经历改写 / 技能排序 / 模块补充）
→ 用户确认方向 → 逐模块执行（每步先展示方案，确认后写入）→ 红线约束
```

### T6 — 每日求职简报模板
ResuAlign 有 reminders/scheduler（跟进提醒），但无「每日简报」产品。
可直接套用的简报结构：
```markdown
# 每日求职简报 - YYYY-MM-DD
## 新增职位（24h 内）      / 表格：岗位|公司|城市|薪资|投递链接
## 即将截止（7 天内）      / 表格：岗位|截止日期|剩余天数|链接
## 新增匹配岗位            / 表格
## 推荐投递 Top 5          / 按匹配度排序，附链接
```

### T7 — ATS 识别 + 经验记录
投递环节最有复用价值的设计：
- ATS 域名特征表：`*.beisen.com`(北森)、`*.mokahr.com`(Moka)、`*.greenhouse.io`、`*.myworkdayjobs.com`、`*.successfactors.com`、`*.smartrecruiters.com` → 自建系统
- 记录模板 `ats-records/{ats-type}.md`：使用公司、最后更新、表单结构（必填/选填）、特殊注意（字数限制、证件照、附件格式）
- 隐私处理：身份证号等敏感字段**提醒用户自行填写，不代填**

### T8 — 触发词 / 路由表
每 Skill 定义触发词 + 明确的「不适用」边界，让意图路由不越界。
ResuAlign 的 `role_router.py` 是 **LLM 角色路由**，参考仓库提供的是**用户意图路由**（"搜索校招"→campus-search），可做成前端命令面板/快捷入口。

### T9 — 示例对话模板
每个 Skill 附 1-3 个完整示例对话（用户说→AI 调用→AI 回应），
是「文档即测试用例」的廉价实现，对调试 prompt 和写用户手册都很有用。

## 4. 项目优点（借鉴项）

1. **单一职责 + 明确边界**：6 个 Skill 互不重叠，每个都写清「不适用」场景，路由清晰。
2. **文档即产品**：Skill 自包含、可独立分发，用户读文档就能用。
3. **全链路闭环**：创建→搜索→优化→投递→监控，任何一步结束都主动引导下一步，用户不会断链。
4. **红线约束系统化**：写作红线统一、显式、所有模块共享，是控幻觉的有效手段（与 ResuAlign「铁律：不捏造事实」同源，但拆得更细）。
5. **隐私保守**：敏感字段不代填，投递数据必须与简历一致。
6. **低门槛示例**：每个流程带完整示例对话，学习成本低。

## 6. 一句话总结

> upcv-clawjob 值得抄的不是代码，而是**「身份差异化的创建向导 + 共享写作红线 + 5 维诊断 + 方向层确认的改写协议 + 每日简报 + ATS 经验复用」**
> 这 6 组设计资产；ResuAlign 工程底座（流水线/版本/Diff/成本守卫）已经更强，缺的是**上游向导和下游投递/简报的闭环**。
