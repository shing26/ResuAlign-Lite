## 本会话完成的工作（`2b6d485`）

背景：`#/workspace/<jobId>` 被静默弹回 `#/dashboard`（Playwright 冒烟暴露，`app.innerHTML` 一直是 dashboard，且无 render error 日志）。

根因有三条，均已修复：

1. **分析任务过期被弹回（主因）**：岗位带 `workbench_job_id`，但对应 analysis job 已被 TTL 清理 → `resumeAlignmentProgress()` 对 `GET /api/jobs/{analysisId}` 404 → 旧代码静默 `location.hash="#/dashboard"`。修复：catch 内只 `stopAlignmentPoll()` 后 return，保持工作台打开，用户可重跑对齐。见 `src/resualign/static/app/split-canvas.js` 的 `resumeAlignmentProgress`。
2. **API/导入岗位无 workbench session**：`loadSession()` 对 `/api/workbench/session/{id}` 与 `/api/workspace/session/{id}` 都 404 时返回 null，旧代码直接回 dashboard。修复：新增 `buildSessionFromJob(job)`，从岗位库落库数据（`jd_profile` / `gap_report` / `diffs` / `final_draft` / `eval_score`）重建三栏 session；`alignment.status` 强制为 `succeeded` 或 `idle`（避免残留 `running` 再触发恢复逻辑）。岗位真不存在（`!existing`）仍回 dashboard。
3. **缺口卡片导航**：dashboard 缺口卡片由 `<a href="#/workspace?skill=...">` 改为 `<button data-action="goto-skill">`，`main.js` 的 goto-skill 改用子串匹配（`===` || `includes` 双向）。同时把 `console.error("render error", ...)` 从误插的 analyze-jd catch 移回 `render()` catch（带 route 上下文）。

验证手段：Playwright 冒烟 `goto #/workspace/bcb5d7bb9a91428eb974e47b92874d17` 后 hash 停留 workspace、`.split-canvas` 三栏渲染（`app.innerHTML` ≈16KB）。无 session 岗位工作台加载时会有 **2 个 404**（loadSession 的两个探测端点），属预期。
