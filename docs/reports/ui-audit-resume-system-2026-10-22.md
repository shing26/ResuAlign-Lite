## 0. 先回答普查里那个问题：是「有意的层级」还是「失控的堆积」？

**结论：字号/圆角/间距刻度是「有意的层级」，但执行层是「失控的堆积」；字重与颜色是两者的混合体。**

| 维度 | 实测分布（census + 复测） | 判定 |
|---|---|---|
| 字号 | token 定 8 档；`font-size` **0 处裸 px**、299 处走 `var(--text-*)`。但简历页 113 个文本节点里 **12px 62 个 + 13px 31 个 = 82%**；桌面驾驶舱 70% 也是 12–13px；全页 ≥15px 的正文只有 4 个（标题/两个分数） | **刻度有意，权重错配**：2 个相邻档承担 80% 信息，11/12/13/14 四档挤在 3px 内，层级读不出来 |
| 字重 | token 只定义 400/500/600 三档；实际声明 115 处里 **110 处裸数字**：700×45、800×31、600×23、500×7、100×2、400×2；仅 5 处用 token | **失控**：同一语义标题在 600/700/800 之间摇摆（页面标题 600、简历标题 700、看板列标题 800） |
| 文字色 | 每页 6–14 种。逐项可映射到 token：`#14171C/#4C5561/#6A7381/#99A1AC` + success/warn/danger/accent-text + `#FFF`；仅 `color(srgb … /0.9)` 是 `body.text-white/90` 的 90% 透明度继承 | **基本有意**；问题在「语义色齐全但缺角色约束」（见 SH-04 / SH-08） |
| 背景色 | 每页 7–18 种；简历页 11 种 = surface 四阶 + 状态 soft 底 + 强调实底，可解释；驾驶舱把 `--text-tertiary` 当背景用 11 次 | **混合**：颜色本身有意，**token 误用**是错误 |
| 圆角 | 实际 4/6/8/12/999 + 1 处 50%：tag=4、按钮/输入=6、卡片=8、面板=12、胶囊=999 | **有意的层级，健康**（不用动） |
| padding | 简历页 20 种组合、工作台 24 种；`padding` 317 处声明里 294 处走 token，`gap` 304 处里 301 处走 token，`margin` 只有 104 处里 50 处走 token | **刻度有意，组合无序**：组件各自挑台阶，缺组件级 padding token（`--card-pad` 等零引用），产生 4 条不同的左边界（见 SH-07） |
| 阴影 | 111 处声明：48 处 `--shadow-none`、5 处 popover、7 处 modal、3 处 toast（浮层用法合规），其余 33 处为 `none` 或自造 inset ring / glow / 状态描边 | **基本守规则**；卡片主动关阴影是好习惯，33 处自造阴影应收成 2–3 个语义 token |
| 断点/结构 | 1616 个顶层规则块、1157 个不同选择器、**296 个选择器被重复定义（多出 459 个覆盖块，28.4%）**；`.topbar` 16 块、`.app-shell` 12 块、`.app-rail` 11 块；63 个 `@media`、**12 种断点**（360/390/480/520/600/640/700/900/901/1023/1024/1100） | **失控的堆积**：不是「多文件模块化」，是同一文件内的 append-only 覆盖层（24 个 `@layer components` 块） |

一句话：**皮肤（刻度）是设计过的，骨肉（组件消费）没有系统；每加一个页面就追加一层覆盖，于是同一零件出现 4 条左边界、2 套移动壳、16 个 topbar 定义。**

## 1. P0：RS-01 简历正文预览不像一份简历，像灰底日志

- **严重级别**：P0（简历中心的核心产出物看起来"坏掉"）
- **证据**
  - 截图 `.scratch/ui-audit-2026-10-22/shots/desktop-resume.png`：中央「完整简历」内是灰底（`rgb(244,245,248)`）上一段 12px 深灰字，无章节标题、无纸张感；`mobile-resume.png` 里同样内容被 40px padding 压成约 20 字/行。
  - CSS：`styles.css:8020-8053`（`.resume-doc` 背景 `--surface-inset`、`padding: 32px 40px 48px`；`.resume-doc p, li { font-size: var(--text-xs) /*12px*/; color: var(--text-secondary); line-height: 1.7 }`；`.resume-doc h2 { font-size: var(--text-base) /*14px*/ }`）。
  - **同一选择器两处定义互相打架**：`styles.css:820-867`（base 层）声明 `h1 24px / h2 20px / h3 16px`，被 `styles.css:8020-8046`（components 层，后者胜出）压成 `h1 24 / h2 14 / h3 13`。也就是说章节标题只比正文大 2px。
  - 实测（1440×900）：`.resume-doc` 744×446.5，内容 `scrollHeight=1949`，即可见 **22.9%**；正文 12px/20.4，内容宽 664px ≈ 55 个汉字/行（远超可读行长 30–40 字）。移动端正文 x=898 才开始（整屏 844）。
  - token 层自己写着 READ 区「不得 <15px」（`styles.css:81-83`），并定义了 `--paper-bg/--paper-ink/--paper-line`（`styles.css:219-229`，`--paper-bg` 只在打印相关规则里用了 7 次，预览一次没用）。
  - 渲染器只认 `#` 标题与 `-` 列表（`format.js:166-203`）；用户这份 3297 字的简历里 `h1/h2/h3 = 0 个`，32 个 `<p>` + 19 个 `<li>` ——「教育经历」「主修：」这类小标题全是段落，所以视觉上连一个章节分隔都没有。
- **用户影响**：点开简历中心，看到的是一段灰底小字，判断不了"这份简历能不能投"；只能再去点「打印预览」才能看到像样的 A4 排版——而按钮就在旁边，等于自证预览不可信。
- **根因**：`.resume-doc`（`styles.css:8020`）把 READ 区当 UI chrome 处理（12px + `--surface-inset`），且 `format.js:renderMarkdown` 不产出文档级结构；纸张 token 已存在但未接线。
- **改法建议**
  1. `.resume-doc`：`background: var(--paper-bg); color: var(--paper-ink); font-size: 15–16px; line-height: 1.55; padding: 40px 56px;` 内容 `max-width: 66ch; margin: 0 auto;`（用 `--paper-*`，暗色下也保持白纸，符合 token 注释的「文档语义」）。
  2. `.resume-doc h2` 提到 18–20px、`font-weight: 600`，h3 15–16px；删掉 base 层那组被覆盖的旧规则（`styles.css:820-867`），只留一处定义。
  3. `renderMarkdown` 里把「纯文本短行 + 下一行含冒号/项目符号」识别为 h3（或至少在编辑弹窗提示用 `##`），把 56 行内容变成 5–6 个可扫的章节。
  4. 行长控制：桌面 66ch，移动端 `padding: 20px 16px`；一节一屏，避免 40px 固定 padding 在 390 屏上吃掉 20% 宽度。
- **预估工时**：5–6h（CSS 2h + renderMarkdown 章节启发 2h + 桌面/移动/暗色验收 1.5h）

### RS-02 一屏 23 个按钮：诊断 3 个入口、导出 5 个入口（3 个同权重）、"85 分"说了 6 遍

- **严重级别**：P1
- **证据**
  - 截图 `shots/desktop-resume.png` 页头区：`诊断简历`（teal 实底）+ `导出简历 MD` + `导出诊断 MD` + `导出诊断 PDF` + `删除`（红字浅底），全部 28px 高、同一排；下方诊断卡内右上角又有一个 `诊断简历`（teal 实底），卡内结果行还有 `去对齐` + `重新诊断`；「完整简历」头部再放 `编辑源码`(teal) + `编辑` + `复制 MD` + `打印预览`。
  - 实测：整页可见按钮 **23 个**（含全局导航 6 个 + 顶栏搜索/主题 2 个），即简历页自身动作 **15 个**；同名主按钮 `诊断简历` **2 个**（Playwright 按文本查重命中 `diagnose-resume` ×2）；85 分相关按钮 6 个：`diagnose-resume ×2 / rerun-diagnosis / diagnosis-to-align / export-diagnosis-md / export-diagnosis`；页面 innerText 中 "85" 出现 **6 次**（页头「最近诊断：85 分」、结果行「85」+「诊断分 85 / 100」、右栏 pill「85 / 100」+ 大字「85 /100」）。
  - 根源代码：`resume-center.js:120`（页头诊断）、`resume-center.js:135`（面板内初始写「重新诊断」）；`events.js:595-609` 诊断成功后把面板按钮文案改回「诊断简历」并在结果行再塞一个「重新诊断」(`events.js:601-602`)，于是一次诊断完成后同屏出现 3 个诊断入口；`resume-center.js:121-123` 三个导出按钮都是 `btn btn-secondary btn-sm`，`resume-center.js:179-184` 又是 4 个同权重按钮。
- **用户影响**：不知道该点哪一个；「诊断简历」点错了要花模型调用（页面写着 5.9s），「删除」还紧挨着导出按钮——这正是"无从下手"的直接来源。
- **根因**：没有「每屏一个主操作」的规则；诊断/导出/编辑入口在页头、诊断卡、结果行、文档卡四处各自生成，且 `events.js` 会在完成态改写按钮文案，造成"同一个动作换名字"。
- **改法建议**
  1. 页头只留一个主 CTA：「诊断简历」（未诊断）/「重新诊断」（已有结果）；诊断卡内不再放按钮，只在无结果时给一行"还没有诊断 → 诊断简历"链接。
  2. 三个导出收成 `导出 ▾` 菜单，分两组：「简历（MD / PDF / 打印）」「诊断报告（MD / PDF）」；诊断报告项在无结果时禁用而不是隐藏（用户才知道有这个能力）。
  3. `删除` 移入页头右侧 `⋯` 更多菜单（二次确认已有，位置也降权）。
  4. 分数只在页头状态行出现一次；右栏 ATS 卡去掉标题右侧的 `85 / 100` pill（与卡内大字重复），保留大字 + 等级。
  5. 「编辑源码」与「编辑」合并：文档头只留「编辑」，进入后提供「源码 / 富文本」切换。
- **预估工时**：3–4h（含事件委托与 `events.js:605-609` 的状态文案同步回归测试）

### SH-01 Ctrl+K「万能输入」里没有命令、没有标题，开场只有一行提示

- **严重级别**：P1
- **证据**
  - 截图 `shots/desktop-command-palette.png`：720×230 的对话框，只有一行输入框（占位「搜索岗位或命令」）、一个 Esc、一行提示「粘贴 JD 文本或输入 JD 链接，确认后自动建库并预分析。」、三个动作；**没有可见标题、没有可执行项列表**，输入框下方 67.5px 的 preview 区只放一行提示，其余是大片留白。
  - 实测：`dialog 720×230.5`，`textarea 584×55`（`rows="2"`，像个多行表单，`index.html:106-113`），`preview 694×67.5`，`headings: []`（`role=dialog` 只有 `aria-label="万能输入"`，`index.html:102`）。输入「产品」后弹 6 条岗位建议（每条 39px，`command-panel.js:40-59`），此时 `确认` 仍可用——2 个字的文本也能当 JD 提交。
  - 顶栏触发器写着「/ 搜索岗位或命令...」（`index.html:79-83`），但 `command-panel.js:212-217` 只绑了 `Ctrl+K`，**"/" 快捷键不存在**；命令本身也不存在（`command-panel.js` 只有「搜岗位」和「粘 JD」两种模式，没有命令注册表）。
- **用户影响**：全局唯一入口打开后"什么也没有"，第一次用的人不知道这里能干什么——与"无从下手"直接相关。
- **根因**：把"JD 录入框"包装成"命令面板"（`index.html:96-125` + `command-panel.js`），没有默认命令清单/分组/快捷键提示，也没有空态设计。
- **改法建议**
  1. 打开即显示默认列表：分成「操作」（新建岗位、进入工作台、切换主题、导出当前简历、打开设置…）、「最近岗位」（前 5 条）两组；输入才切换为搜索结果。复用现有 `.command-palette__suggestions` 容器即可。
  2. 对话框加可见标题「命令面板」+ 右上 `Esc`；首行 hint 改成"输入岗位名搜索，粘贴 JD 文本或链接新建"。
  3. `确认` 仅在 `trim().length >= 30` 时启用（`command-panel.js:setPreview`），避免 2 个字建库；搜索结果模式下 `确认` 改为"打开选中岗位"或隐藏。
  4. 要么实现 `/` 聚焦（`document` keydown: 非输入态且 key === "/" → preventDefault + open），要么把占位符里的 `/` 去掉。
- **预估工时**：4–6h（命令注册表 2h + 空态/分组 1.5h + 快捷键与禁用态 1h + QA）

- **严重级别**：P1
- **证据**

- **根因**：设计系统只完成"定义"，没有完成"收口"：没有 lint 拦裸值、没有删除旧路径、组件 token 没人用；Tailwind 迁移只搬了类名没搬语义。
- **改法建议**
  1. 不新增 token 层；先做"接线或删除"：把 `--btn-*` 等别名真正用进 `.btn` 规则（约 30 行），死布局 token 要么接线（`--sheet-max` 用在 `.resume-doc` max-width，`--inspector-w` 用在 resume-rail 宽度）要么删。
  2. 给 `tests/frontend/` 加 lint：`src/resualign/static/` 下（除 styles.css 的 tokens 段）禁止 `#[0-9a-f]{3,8}`/`rgba(`；JS 模板禁止 `style="` 里出现 px 字面量。当前会命中 resume-center.js/format.js/split-canvas.js，作为棘轮逐文件清零。
  3. 把 168 处 `color-mix` 中"边框/底色"类收敛到 `--line-*`/`--surface-*`，只保留 hover/焦点/光晕类派生。
  4. 明确渐变政策：允许 conic 分数环（改注释），删除点阵 radial，统一到 `--score-color`。
- **预估工时**：6–10h（lint 2h + 别名接线 2h + JS 字面量清理 2h + 渐变/数字栈 1h + 回归）

### SH-09 对话框可达性：关闭后焦点丢失、背景没有 inert、占位符对比度不足

- **严重级别**：P2
- **证据**：`command-panel.js:129-139` 关闭面板只 `input.blur()`，**不把焦点还给触发按钮**；`index.html:96-125` 的遮罩与背景没有 `inert`/`aria-hidden`（焦点陷阱只在 Tab 时循环，屏幕阅读器仍可读到背景）。对话框 `role=dialog aria-modal=true` 但无可见标题（`index.html:102`）。对比度：占位符 token `--field-placeholder = --text-faint #99A1AC` 在白底 **2.61:1**、在 `#F4F5F8` 上 **2.39:1**（`styles.css:469`），低于 4.5:1；成功徽标 `#1A7F4B on #E7F5EC` = **4.47:1**（11px 小字，略低于 4.5）。
- **用户影响**：键盘用户 Esc 关闭后"焦点没了"，再 Tab 要从未知位置重新走；读屏用户会漏到背景内容；浅灰占位字在亮屏户外几乎看不见。
- **根因**：`focus-trap.js` 已有 `restoreFocus()`，但 command-panel 自己写了一套内联陷阱、没有复用；缺 `inert` 增强；占位符色用了"装饰级"的 faint。
- **改法建议**：`openCommandPanel` 记录 `document.activeElement`，关闭时 `restoreFocus()`；遮罩层用 `showModal()` 或给 `#app-router-view`/`rail` 加 `inert`；占位符改用 `--text-tertiary`（4.4:1 仍差一点，可 `color-mix` 压深到 ≥4.5）；成功徽标换 `--success` 深一档。
- **预估工时**：2–3h

### SH-10 全局态：加载只有一句「加载中...」，错误只有一块英文 message panel，空态只有一种

- **严重级别**：P2
- **证据**：`main.js:332` 每次路由先塞 `<div class="skeleton is-shimmer">加载中...</div>`，随后简历详情再换成结构化骨架（`resume-center.js:287-307`），但列表/驾驶舱/设置没有再细化的骨架；错误只有兜底 panel（`main.js:341-358`）`<h3>出错了</h3><p>${error.message}</p> + 重试`，直接透出 `error.message`（可能是英文/技术文案），没有危险色、没有 request_id、没有"本地数据还在"的安抚；空态只有简历列表那一处（`resume-center.js:78-84`），诊断/ATS 的空态是 `atsHealthCardHtml(null)` 的一行字（`format.js:3156-3174`）。
- **用户影响**：慢的时候只看到一句"加载中"不知道在等什么；出错时看到技术报错会以为数据丢了；空态没有下一步动作引导。
- **根因**：态设计没有组件化（`--empty-*` 5 个 token 全部零引用，`--skeleton-*` 2 个只被基础骨架用）；错误页是最后兜底而非产品态。
- **改法建议**：抽 `<state-panel type="error|empty|loading">` 组件（图标 + 人话标题 + 一句解释 + 一个动作）；错误文案映射 `code`（已有 `request_id`/`message` 契约）；每页给骨架（复用 `.skeleton` token 色）。至少把 `error.message` 换成"加载失败，请重试（已记录 request_id）" + 可展开技术细节。
- **预估工时**：4–6h（组件 2h + 6 路由接入 2h + 文案）

### SH-11 深色模式首屏闪白：主题只在 JS boot 后应用

- **严重级别**：P2
- **证据**：`theme.js:45-48` 的 `initTheme()` 由 `main.js:4012` 的 `boot()` 调用；`index.html:3-9` 里没有 pre-paint 内联脚本；`applyTheme` 靠 `document.documentElement.classList.toggle("dark")`（`theme.js:21-31`）。模块加载 + 脚本执行期间，页面按 `<html>` 默认（light token）绘制。
- **用户影响**：深色用户每次刷新都先闪一下白，然后变黑；晚上很刺眼（如果系统是深色）。
- **根因**：主题类在客户端应用，且没有在 `<head>` 里阻塞式读取 `localStorage`/`prefers-color-scheme`。
- **改法建议**：在 `<head>` 内加 10 行内联脚本，读 `resualign_theme` 或 `matchMedia`，立即给 `<html>` 加 `class="dark" data-theme="dark"`；`theme.js` 保持不变（幂等）。或 `<meta name="color-scheme" content="light dark">` + `@media (prefers-color-scheme)` 兜底。
- **预估工时**：1h

### SH-12 动效 token 一半没接、reduced-motion 靠 4 份重复 blanket 兜底

- **严重级别**：P2
- **证据**：44 处 `transition` 只有 26 处用 `var(--dur-*)`，22 处 `animation` 只有 10 处用；原始时长混用 `0.15s`（8 处）与 `160ms`（9 处）、`180ms`（6 处）、`0.12s`（3 处）。`@media (prefers-reduced-motion)` 的 blanket 规则复制了 4 份（`styles.css:11666/11818/11867/11963`，另有 11931/11957 两处组件级补充），当前功能是有效的，但每份都新增维护点。
- **用户影响**：动效节奏不统一（有的 120ms 有的 180ms），用户感知是"点击反馈忽快忽慢"；reduced-motion 目前没坏，但后续新增组件容易漏。
- **根因**：动效 token 定义了 4 档但组件直接抄数字；reduced-motion 也是 append-only。
- **改法建议**：全局替换为 `var(--dur-fast/base/slow)`（约 30 处）；把 4 份 blanket reduced-motion 合成 1 份（`@layer overrides` 末尾），并保留两处组件级补充。
- **预估工时**：2h
