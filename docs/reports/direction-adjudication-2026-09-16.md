## 0. 结论摘要（一屏读完）

1. **你不缺方向。** 方向已在 2026-09-14/15 由 ADR-0040 + ADR-0041 裁定完毕：
   skill 探针升主线、app 冻结一切新功能、4 周行为判据决定生死。11 项裁决逐题落定。
2. **你缺的是那一步「不是写代码」的执行。** 探针发布包里有两项人工动作
   （置顶 first-run 讨论、四渠道 outreach），**至今未做**；而判据时钟已经启动
   （09-15 → 10-13，今天 09-16，**只剩 27 天**）。
3. **关键机制：不行动不是中立选项。** 判据下限是「4 周后非作者首跑 < 2 例」= 证伪；
   outreach 不发 → 0 例 → 触发证伪 → 按决定 10，skill 线冻结、回 app-only。
   而 app-only 的证据（59 租户 0 真人、全表 accepted=1）已说明那条路没有外部需求。
   **不作为的实际结果是退回到一条已被实测证明没有需求的路。**
4. **推荐主轴**：把「自用优先（用你的秋招当探针）」升为主干，把原探针判据
   降为并行的「上行期权」。理由不是它更舒服，而是它**在你 27 天可控范围内**
   （见 §5）。
5. **前置动作（必须现在做，且必须在看到任何结果前）**：以预注册方式重锚判据与时钟，
   写成一版 ADR-0042。不改这一条，下面的推荐就无法执行——因为合同会先终止项目。

## 2. 方向为什么「已经定了」——把已有裁决压缩成一页

**ADR-0040（09-14，三线门槛）**：Phase A 不再由 Phase 0 自动放行，需三线全亮

| 线 | 内容 | 当前 |
|---|---|---|
| 能力线 | Phase 0 过线（8 cell） | 待跑，结论已悬置 |
| 地基线 | 真实对齐成功率回可接受线；零 diff 假成功被 CI 锁死 | false（可接受线 09-15 定为：连续 8 例 ≥7 例 usable_diffs≥1） |
| 需求线 | (a) 同一简历 ≥3 轮改→评→改，≥1 轮采纳，≥2 轮因果链 ≥ 3 例 | **1 例**（09-15 狗食两跳链） |

**ADR-0041（09-15，掉头裁决）**：11 项逐题裁决，核心是

- 决定 1：app **冻结一切新功能**
- 决定 2：探针形态 = prompt skill + **单文件确定性验证器**（fabrication gate 是代码不是承诺）
- 决定 4：判据（4 周）——过 = ≥5 例非作者首跑（附 GATE 行）或 1 例外部完整合格链；
  强信号 = ≥100★ 或社区二创；**证伪 = 非作者首跑 < 2 例**
- 决定 9：过 → skill 升主线，app 降为可选持久层
- 决定 10：**死 → 归档条款（合同，不复议）**：证伪 → skill 线冻结、回 app-only、
  不开第三条线
- 决定 11：漂移锁三道（fixtures 唯一事实源 + vendor 副本 + 双侧断言）

> 所以「这个项目要做成什么」在 09-15 已经有了书面答案：
> **一个「防编造的简历对齐 skill」+ 它背后的持久化 app**，且当前阶段的任务
> 不是写功能，而是**验证有没有陌生人要它**。

### 3.2 不作为的后果推演（按你自己的合同）

1. outreach 不发 → 探针零曝光 → 非作者首跑 = 0
2. 0 < 2 → **证伪**（决定 4）
3. 证伪 → **skill 线冻结、回 app-only、不开第三条线**（决定 10）
4. 且 (a) 目前 = 1 ≠ 0，所以**不会**触发「README 挂 maintenance、全 Phase 冻结」
   ——这一步被你 09-15 的狗食动作挡住了

> **结论：不作为 = 项目主线被冻结、退回 app-only。**
> 而 app-only 这条路，你自己的数据已经判过：59 个租户里 58 个是测试流量，
> 唯一真人中断于 08-17，全表采纳 1 次。**不作为不是「等等看」，是选了一条已知走不通的路。**

### 3.3 一个必须先说清楚的测量问题

ADR-0041 决定 4 把时钟起点钉在「转公开时刻」（你当时的理由：「宁可早停表」）。
但 outreach 至今未发 → 这 27 天里有相当一部分是**没有暴露的静默期**。

如果不处理，你会在「几乎没人看过」的状态下被判证伪。**那是测量错误，不是方向错误。**

决定 10 明令「事后不许凭感觉谈判」——所以重锚必须**现在做**，
在看到任何结果之前、白纸黑字写下来。这在方法上叫预注册（pre-registration），
是**合法且更严格**的做法，不是给自己开后门。

## 5. 推荐路径

### 5.1 推荐组合

> **主轴 = B + D（自用优先 + 求职资产转化）；A 的最小分发动作作为并行「上行期权」；C 明确不做。**

| 角色 | 方向 | 占总精力 | 判据 |
|---|---|---|---|
| 主干 | **B 自用优先** | ~40% | 需求线 (a) 1 → 3 例 |
| 主干 | **D 求职资产转化** | ~40% | 面试能讲透 provenance 门禁与掉头裁决 |
| 期权 | **A 最小分发** | ~15% | 开启探针判据，不承担生死责任 |
| 不做 | C 基础设施 | 0% | 探针出结果前不重开 |

### 5.2 为什么是这条（三条理由，都可核对）

1. **你的瓶颈是能力+日历，不是意愿。** 分发能力在 6 个月里被实测为 0；
   27 天内补不上。而自用是 100% 可控的。
   把项目生死押在你从未行使过的能力上，是**风险错配**。
2. **秋招窗口 = 探针窗口。** 9–11 月与 09-15→10-13 几乎完全重叠。
   这是把这个工具用在自己身上的**唯一自然时机**；错过要等明年春招，而合同不等人。
3. **B + D 各自点亮一条你能独自控制的线。** B 点需求线 (a)——三线门槛里
   唯一你能单方面点亮的一条；D 把你半年的投入直接换成 offer 概率。
   两者都在你手里，都不依赖陌生人。

### 5.3 前置裁决：重锚判据与时钟（**必须在结果出现前完成**）

建议新增 **ADR-0042**，改三处，其余不动：

| # | 现状（ADR-0041） | 建议改为 |
|---|---|---|
| 1 | 时钟起点 = 转公开时刻（09-15） | 时钟起点 = **四渠道 outreach 全部发出当日**；若 09-23 前未发，则登记为「分发未执行」而非「探针证伪」 |
| 2 | 单一判据（非作者首跑） | **两条独立线**：探针线（非作者首跑，口径不变）∥ **自用线**（(a) ≥3 例，口径 = 需求线 (a) 原样） |
| 3 | 证伪 → 归档（决定 10） | 归档触发条件从「探针证伪」改为「**探针证伪 ∧ 自用线 = 0**」；探针单线失败只冻结 skill 线，不冻结项目 |

- 必须在**现在**、看到任何首跑数据之前落笔；看到结果后再改 = 违反决定 10，无效
- 自用线的取证必须走验证器 JSONL（`round` / `trigger` / `chain` / `resume_sha256`），
  不接受口头复述
- 探针线的「过/强信号」口径**一个字不改**
