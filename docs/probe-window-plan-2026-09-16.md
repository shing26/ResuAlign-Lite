## 4. 自用线执行细则（1 → 3 例）

### 4.1 一例合格的定义（三条全满足）

同一份简历 **≥3 轮「改→评→改」** ∧ **≥1 轮有 diff 被采纳** ∧
**≥2 轮的触发原因是上一轮评测结论**（因果链条款）。

### 4.2 每一例的操作序列

```bash
# 工作目录：每投一个岗位一个新目录
#   resume.md（母版简历）、jd.txt（真实投递过的 JD 原文，别用链接）

# 第 1 轮
python <gate_path> --resume resume.md --diffs diffs.json --allowlist gap.json \
  --log tailoring.jsonl --round 1 --trigger manual

# 采纳（应用 diff 时复跑门禁；blocked 的 id 写不进去）
python <repo>/apply.py --resume resume.md --diffs diffs.json --allowlist gap.json \
  --accept <diff_id> --out resume.r1.md

# 第 2 轮起：trigger 必须引用上一轮评测结论
python <gate_path> --resume resume.r1.md --diffs diffs2.json --allowlist gap2.json \
  --log tailoring.jsonl --round 2 --trigger eval:round1
```

- `gate_path`：Claude Code `~/.claude/skills/true-tailor/gate.py`；Codex `~/.codex/skills/true-tailor/gate.py`。
- 每轮收尾在清单 §4 记录表补一行（round / trigger / diffs / usable / blocked /
  `resume_sha256` / `cites_prev`）。
- **推进节奏建议**：投一个岗位就当场跑完，不要事后补——补跑必然丢掉因果链。

### 4.3 五个会让这一例作废的失效模式

| # | 失效 | 后果 |
|---|---|---|
| 1 | 第 2 轮起漏传 `--trigger`（吃默认 `manual`） | `chain.cites_prev = false` → 因果链不成立 |
| 2 | 只跑 2 轮 | 不满足 ≥3 轮 |
| 3 | 用 `examples/demoflow` 合成例、截图、口头复述 | 护栏 6c：一律不计 |
| 4 | JD 不是真实投递过的岗位 | 护栏 6d：不计入 (a) |
| 5 | 用 `apply.py` 以外的方式把 diff 写进稿子 | 「采纳」缺少可复核证据 |

> 目标：**还需 2 例**。可以是另外 2 个真实岗位，也可以是同一简历的第 2、3 条轮次链。
