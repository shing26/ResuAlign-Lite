# 断层诊断与体验改进路线图 — ResuAlign 求职工作台

> 日期：2026-08-27
> 触发：产品侧观察「AI 工程与真实体验存在断层——架构分层清晰、测试全量飘绿、
> 状态机滴水不漏，但一上手真实使用，总觉得机械、平淡、差点意思」。
> 方法：对 2026-08-15 至 2026-08-25 的六轮 QA 报告（8-15 体验报告、
> 8-19 Round2、8-21 Round4、8-17 dogfood、8-25 persona 走查、8-25 R5 DOM
> 走查）做交叉归因，结合 `src/resualign/static/` 实况代码与 phase-17/18
> 设计资产逐项核对。

---

## 0. 一句话结论

**断层不在功能，在验收文化。** 项目六轮 QA 修的全部是「机器行为是否正确」
（状态、一致性、可达性、降级、无报错），无一轮验收「人的理解是否正确、这个
时刻用户该 feel 什么」。「测试全绿」验证的是状态机没有漏，而「机械、平淡」
恰恰来自状态机词汇直接充当了用户体验词汇。

又是同一类——**所有轮次都在同一平面上打地鼠：正确性平面。没有任何一轮
进入体验的第二平面：叙事与情感。**

## 2. 断层定位：四层 + 一个根

### L1 归因失真 —— 机器错误被翻译成误导

状态机把错误分得很细（queued/running/succeeded/failed/canceled/expired），
但错误文案把分类抹掉了：

- **Round4 Bug-01 实锤**：对齐 2/2 必败，日志是
  `pydantic ValidationError: TailoredResume.sections 工作经历 input is dict`——
  **模型返回的是合法 JSON，只是字段形态不符**。UI 文案却是「模型返回了空内容
  或无法解析的 JSON」——两个都是事实性错误归因。
- **persona P0-1 实锤**：模型超时 166s，横幅写「模型响应超时，请检查 API Key
  与网络连接后重试」，而 `/api/settings/status` 显示 Key 有效、连通 2437ms。
  「检查 Key」是纯误导，用户照做无效还要再烧 2 分钟。
- **8-19 Bug-04**：额度/超时错误直接 500 + 「Internal Server Error」丢给用户。

> 一句话：**状态机知道错了什么，文案却不知道。** 后端有 error 分类的能力
> （超时/结构/额度/网络），前端却用一条笼统文案兜住所有类别。这是「AI 工程
> 正确、真实体验错误」最刺眼的一处。

### L2 词汇分裂 —— 状态机词汇直接当用户体验词汇

- 用户看到的按钮：`开始优化` / `开始对齐` 两个动词并存（persona P0-2 实测
  同屏 3 个入口 2 套标签）；空态引导说「点击*右侧顶部*『开始优化』」，实际
  按钮在画布中部、叫「开始对齐」。
- 同语义字段两种数据源：卡片状态下拉用内置常量，筛选/编辑用设置词表
  （persona P1-2/R5 P1-2 已修卡片侧，但 R5 报告自己承认 value 编码仍
  canonical key vs 词表原文并存——修的是一处，裂的是体系）。
- 状态 `failed` 与 `idle` 渲染完全相同（Round4 Bug-09）：用户分不清「没跑过」
  和「跑失败了」——**状态机里有 failed 态，体验里没有失败感**。
- 用户侧词汇缺失：产品从不回答「这个岗位值不值得押」（决策词），只回答
  「这条记录是什么状态」（状态词）。驾驶舱是 KPI 面板，不是决策台。

### L3 脚手架外泄 —— 工程内部结构直接可见

- 岗位库躺着测试岗「多行解析验证52200资深后端工程师」（persona P2-3）。
- 设置页节点名 `.env 默认` / `omniroute` / `nvidia`（内部命名原样展示）。
- 驾驶舱「最近岗位动态」显示的字段是 `updated_at`——对齐失败也刷新它，用户
  凌晨看到「未投递 · 03:45」会以为发生了什么（persona P2-3）。
- 8-15 报告：导出菜单「已生成」徽标分不清指「草稿已生成」还是「已导出过」。

> 一句话：**这些不是功能缺陷，是「把调试视图当产品视图交付」的习惯。** 每个
> 单项都很小，合起来就是用户感知里的「这是工程产物，不是为我做的工具」。

### L4 信息无节奏 —— 每帧塞满，不引导视线

- 简历列表每卡整份 Markdown 全文（1206×276px × 6 = 1656px，persona P2-5）。
- 岗位卡一张卡 9 个操作 + 状态下拉 + 复选（persona P2-1）；诊断 ×2、导出 ×2、
  对齐 ×3、投递 ×2。
- 技能缺口把 JD 长句当技能渲染成整块横幅（persona P1-5）：AI 输出直接堆给
  用户，没有短语化加工——**AI 的智能没有被做成「用户可扫读的结论」**。
- 设置页六个大区块 5 个独立保存按钮分散在不同 x（persona P2-6）。

### 根：验收文化只有「正确性」一个维度

R5 的验收表是 PASS/FAIL 清单（词表同源 ✅、失败标识 ✅、底栏最小集 ✅）。
没有任何验收项长这样：
「新用户林然第一次打开工作台，30 秒内能否说出『这个岗位我该不该投』；
失败时他能否说出『是模型慢、还是结构坏、还是我的问题』」。
**产品长成了检查清单的样子，因为验收只检查清单。**

## 3. 为什么「测试全绿」和「体验机械」可以同时成立

测试验证的是**状态机的闭包**（每个状态都可达、可转换、可持久化），不是
**人的理解的闭包**（每个界面时刻都说得清、指向清、不失真）。两者交集有限：

| 机器测的（全绿 ✅） | 人实际遇到的（全漏 ❌） |
|---|---|
| queued→running→succeeded 转换正确 | 失败时文案归因错（L1） |
| failed 状态落库 | failed 与 idle 视觉相同（L2） |
| 词表三处同源 | 动词两个并存（L2） |
| 11 卡全同源 | 测试岗躺在库里（L3） |
| 无横向滚动 | 简历列表 1656px 全文（L4） |
| prefers-reduced-motion 全部归零 | 没有一条验收「保存时你 feel 到了确认」（根） |

**同一个 state machine，两种读法。** 机器读它验收通过，人读它才刚入门。

## 4. 改进路线图（按「信任」优先排序）

> 原则：先修「让用户觉得自己被骗/被误导」的（扣分项），再修「让用户感到
> 被理解」的（加分项）。本地工具最大的资产是信任，当前 L1/L3 在主动扣分。

### P0 — 信任修复（文案层，1-2 天）

| # | 动作 | 落地点 | 验收 |
|---|---|---|---|
| T1 | **错误文案按类别分类**：超时→「模型响应慢（耗时 Xs），可换更快模型或缩短 JD 重试」；结构→「模型返回结构异常，已尝试自动修复」；额度→「额度/欠费」；仅真空内容才说「空内容」；网络类才提 Key | `api/services/jobs.py` 失败映射 + `split-canvas.js:1283-1297` | 用 Round4 锚点岗位和 fake LLM 分别触发四类错误，文案逐类命中，不再出现「检查 Key」误导 |
| T2 | **全站动词统一为「开始对齐」**，空态引导与真实 UI 控件位置/名称逐字一致 | `format.js`（workbenchPrimaryButtonHtml/empty-state）、`split-canvas.js`、`main.js` | persona P0-2 剧本重走：引导文案指向的按钮真实存在且同名 |
| T3 | **失败态有「失败感」**：failed/canceled/expired 主按钮「重新运行对齐」+ 持久错误条（R5 已做驾驶舱侧，补工作台侧回归确认），刷新后仍可见 | `split-canvas.js:615-647 reconcileAlignmentFailure` | F5 后失败信息仍在 |

### P1 — 身份还原（数据卫生，1 天）

| # | 动作 | 落地点 | 验收 |
|---|---|---|---|
| T4 | 清理测试岗位（标题含「验证/测试/52200」白名单确认后删） | 数据迁移脚本 | 岗位库无脚手架残留 |
| T5 | 节点名改可读名（节点 1/2/3 或产品名） | 设置页渲染 vs 内部 env | 设置页无 `.env 默认`/`omniroute` |
| T6 | 「最近岗位动态」改用最近快照/投递动作时间，不再用 `updated_at` | `api/routers/dashboard.py` | 对齐失败不再刷新动态时间 |

### P2 — 叙事建立（语义层，2-3 天）

| # | 动作 | 落地点 | 验收 |
|---|---|---|---|
| T7 | **驾驶舱从 KPI 面板变决策台**：快速继续不再推「最新 updated_at」而推「最近 24h 有进展」；给「可决策」岗位（值得投/要补什么）一行结论 | `dashboard.py:quick_continue` | persona 林然打开驾驶舱能说出「现在最该做的一件事」 |
| T8 | **AI 输出加工成结论**：技能缺口短语化（顿号/逗号切分 + 长度阈值，>12 字或含「或/等」不进）；对齐结果给「一句话：这份简历与 JD 的差距主要是 X，已改写 3 处」 | `dashboard.py skill_gaps` 抽取 + `format.js` 渲染截断 | 驾驶舱无整句 JD 横幅；工作台结果顶部有结论句 |
| T9 | **空态不再撒谎**：无结果/失败/过期三种空态文案与按钮分离；统一「还没有对齐结果」语义，靠状态而非插画区分 | `format.js empty-state` | persona P0-2 重走通过 |
| T10 | 简历列表卡片化：标题/时间/诊断分/版本 + 2 行摘要，全文留给档案页 | `resume-center.js` | 列表页高度 < 600px |

### P3 — 温度注入（体验层，2-3 天，可并行）

| # | 动作 | 落地点 | 验收 |
|---|---|---|---|
| T11 | **成功时刻有确认**：保存定稿的 toast + 卡片顶部绿色色带（phase-18 2.6 脚本已有 CSS `saved-band`，确认 JS 侧在 `save-final-draft` 后挂了 `is-saved`）| `split-canvas.js` + `styles.css` | 保存后 toast 与色带同时出现，文案一致 |
| T12 | 运行中的「慢 vs 卡死」可读性：进度条旁展示当前 LLM 调用耗时与重试次数 | `split-canvas.js` + `main.js` | 用户能说出「它在跑，不是卡了」 |
| T13 | 入口收敛：简历页诊断/导出收进「更多 ▾」；「去投递↗」改名「打开招聘页」（不同文件来源用词区分） | `resume-center.js`、`kanban.js` | 同屏无重复动作标签 ≥2 |

### 机制层 — 把「体验叙事」纳入验收（一次投入，长期生效）

1. **每轮 QA 固定跑「林然第一次使用 30 分钟」剧本**：新数据目录 + fake LLM，
   只走主路径；结束前让走查者回答三个问题——
   「这岗位我该不该投？失败是模型慢还是我错了？数据是安全的吗？」
   任一答不出即记 P0 体感缺陷。现有 `scripts/qa_dogfooder.py` 加一个
   `--narrative` 变体即可。
2. **用户可见字符串集中管理**：把 `format.js` 176KB 里的 UI 文案抽成
   `src/resualign/static/app/i18n.js`（至少抽词汇表：动词、状态、空态、错误），
   加一条 CI 测试断言「文案不漂移」（同义词 "开始优化/开始对齐" 不允许共存）。
3. **缺陷单加「用户视角」字段**：修复验收除了「代码正确」，附一句
   「用户此刻的体验是什么样」，写不出来的修复不允许合入。

## 5. 先动手哪三件（理由）

1. **T1 错误文案分类**——它是「AI 工程正确、体验错误」最刺眼的实例，且
   修复面最小（一处映射 + 一处渲染），对信任扣分影响最大。
2. **T2 动词统一 + 空态对齐**——persona 两名用户的第一视角都撞在这上面，
   0.5 天可完成，直接消除「迷路感」。
3. **T7 驾驶舱决策化**——它是「叙事层」的最小实验：改选择策略 + 一行结论
   文案，跑一轮新叙事验收，再决定是否铺开 T8-T13。

## 6. 附：设计资产核对结论（防误判「没设计」）

- phase-17/18 视觉/品牌/动画资产**存在且落地**：`styles.css` 有
  `card-enter`、`rsa-diff-reveal`、`saved-band`、`--stagger-step`、
  `prefers-reduced-motion` 全套归零规则；toast 微文案表也写过
  （「已保存 · 第 2 版」等）。
- **结论**：断层不在视觉语法，在叙事语义与文案层——动画是「美」，但用户
  感知的「机械」来自「说的话」（L1/L2/L3）和「信息节奏」（L4），不是动效。
  后续设计投入应转向**文案系统与结论生成**，而非再加视觉资产。
