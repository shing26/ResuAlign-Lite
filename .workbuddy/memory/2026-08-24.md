## LLM/Agent 架构优化建议（AI Engineer 视角）
- 交付：`D:/WorkBuddyData/ResuAlign-LLM-Agent架构优化建议.md`（8 维度：模型选型/上下文/规划工具/记忆/多agent/自愈/成本/可观测，含现状基线表 + P0-P2 落地表）。
- 关键架构事实（已核实）：role_router 按角色路由 llm_nodes + 分级超时 + fallback；context_budget 用 len//4 估算（中文失真）+ truncate/select 压缩（破坏性）；graph/ DAG 执行器 + ProvenanceGate/AntiHallucinationGate + retry_count；llm.chat_structured 对 ValidationError 有一次纠正性重试；ContentCache 有 TTL 但无过期清理；cost_guard 按日调用次数封顶 + llm_usage 估成本；observability 结构化日志/请求ID/脱敏/指标窗口。
- 核心建议落点：① 结构纠正重试需覆盖 dict→str 展平 + 语义降级(DEGRADED 而非静默 FAILED)，直击 Round4 Bug-01；② 缓存过期清理；③ tokenizer 真实计量 + 语义保留压缩；④ 任务状态持久化（去 30min session TTL）；⑤ prompt 版本化 + 离线评估集(Golden Set)；⑥ 多 agent 角色契约化 + MCP 收敛。

## ResuAlign vs pm-workbench LLM 框架对比（AI Engineer）
- 交付：`D:\WorkBuddyData\ResuAlign-vs-PM-Workbench-LLM框架对比.md`
- 结论：两者不同层级——pm-workbench 是「AI 接入层」（app/api/chat/route.ts 90 行 OpenAI 兼容代理 + aiClient chatOnce/chatStream + f3ai 3 个硬编码提示词单轮调用，无重试/缓存/编排/观测），ResuAlign 是「Agent 编排层」（role_router 5 角色 + llm_nodes 多租户多节点 + graph/DAG + JSON 4 层修复链 + 纠正性重试 + ContentCache + cost_guard + observability）。15 维度 ResuAlign 胜 12、平 2、pm-workbench 仅 SSE 透传简洁性略优。
- 判断标准：按架构质量 ResuAlign 显著更好；按复杂度匹配度 pm-workbench 极简模式适合 MVP/单轮生成。演进关系非竞争关系。
- 借鉴建议：pm-workbench 先补结构化输出兜底（字符串前缀匹配易静默丢数据）+ 有限重试；ResuAlign 可借鉴其 SSE 透传简洁性与「一次一问」交互壳。
