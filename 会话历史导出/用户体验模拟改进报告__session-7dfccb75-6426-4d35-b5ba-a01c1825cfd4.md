## 核心发现摘要（按严重度）

**🔴 阻塞 · 交互逻辑**
1. **对齐主路径实况失败**：真实点击「开始对齐」→ 166s 超时失败，横幅却提示「请检查 API Key 与网络」（实测 Key 有效，根因是模型超时护栏）。错误归因让用户去做无效动作，是全站最可能流失的点。
2. **工作台失败态混乱**：同屏 3 个对齐按钮、2 套标签（开始对齐 / 重新运行对齐），空态引导文案「左侧优化设置 / 右侧顶部开始优化」与实际 UI 三处对不上。

**🟠 高 · UI / 模块联动**
3. **简历档案页隐藏编辑器默认可见**（styles.css 中 `.hidden` 被后写的 `display:flex` 覆盖）：整份简历源码在预览下方重复出现——对「怕丢数据」的核心用户是信任崩塌级 bug，修复只需 0.5 天。
4. **设置词表联动断裂**：岗位库筛选/编辑走自定义词表，但卡片状态下拉走硬编码，同一页面两套状态源。
5. **驾驶舱「快速继续」把失败任务当「待分析」推荐**，点进去就是失败横幅。
6. **移动端工作台 tabs 深埋 1500px**，关闭按钮仅 9×18px。
7. **技能缺口把整句 JD 要求当技能**渲染成横幅卡。

**🟡 中**：简历「去对齐」深链丢简历上下文；「待跟进」48h 文案与后端口径不一致；同一动作多入口（诊断×2/导出×2/对齐×3/投递×2）；添加岗位内联表单 688px 巨幅展开致布局跳变；测试数据残留、触控目标 28px、简历卡全文预览过载、设置页 5 个分散保存点等。
