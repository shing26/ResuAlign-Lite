## 一页摘要

### 核心节奏设计结论
- **失效全链路改为「主 1 + 次 ≤2 + 更多 ▾」**：任何时刻工作台只有一个状态驱动主 CTA（开始对齐→对齐生成中→重新运行对齐），横幅不再放第二个按钮。
- **失败按 code 分类引导**（需后端补 `failure_code`）：超时「⏱ 不是 Key 问题，是模型慢」+ 阶段耗时明细折叠；结构/空内容给对应修复按钮；只有 auth 类才允许提「查 Key」。第 1 次失败给解释、第 2 次推「换用备用节点重试」（主）、第 3 次建议暂停 + 24h 硬闸「今日还可重试 N 次」防烧额度；换节点重试默认「仅本次生效」，勾选才改全局设置。
- **等待期过程可见性**：已有阶段进度条基础上，补「预期 1-3 分钟」、阶段耗时明细、>60s 心跳动效 + 等待期小步提示「可先去优化设置确认主简历」。
- **模块联动各给一个「下一步」**：词表保存 toast 升级为「已同步岗位库 N 处」+ 一次性同步提示条；快速继续失败任务改警示卡「上次失败·重新运行」、全失败时换「去设置换节点」；简历深链带「已带入简历」徽章并自动绑定，无岗位时只引导「先选岗位」；待跟进文案统一「未过期待跟进」。
- **核心链路节点化 Fogg 设计**：粘贴 JD→对齐→采纳（每 3 条轻庆祝+采纳进度）→保存定稿（步骤条打勾+微庆祝）→记录投递（预填今天自动推进）→安排跟进（预填 2 天后），每节点明确 M/A/P 与频率上限。

### 给 UI 设计师的 5 个开放问题
1. 失败横幅「换备用节点重试」（主）vs「直接重试」（次）如何避免重现 P0-2 的「双主按钮」观感？
2. 阶段耗时明细放进度条内联展开还是右侧抽屉？390px 移动端只能保留一个，选哪个？
3. ⚡ LLM 消耗标记（诊断/对齐/重新评分）的全局规范是否统一，开始对齐确认行是否显示「本次消耗 1 次调用」？
4. 采纳进度条（本次对齐内）与步骤条（定稿→记录→跟进，整个闭环）如何垂直分层不打架？
5. 「今日还可重试 N 次」的展示形态：横幅小字 / toast / 只置灰不做数字？

### 最影响完成率的 3 个引导改动
1. **P0-1 失败分类化 + 「换用备用节点重试」一键闭环**（6/11 对齐成功率、一次失败即流失点的直接修复，含节流硬闸防止烧额度反噬信任）；
2. **P0-2 失败态收敛单入口 + 空态三步文案与真实控件逐字对齐**（次 Persona 第一步就迷路的问题，首次会话从进页到点「开始对齐」目标 <15s）；
