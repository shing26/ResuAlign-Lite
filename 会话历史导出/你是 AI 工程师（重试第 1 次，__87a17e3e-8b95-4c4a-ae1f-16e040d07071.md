## 一页摘要

### 调用侧根因结论
166.2s 不是单个护栏失效，而是**护栏语义错位 + 重试组合累加**：主路径（engine.run 对齐，非 workbench.py，但两处同构）中「30s 角色超时」实为 **httpx 空闲读超时而非法墙钟**——慢模型持续吐字节时单腿可 60-90s 不触发；`call_with_role` 主/备双节点腿 + schema 解析失败后的**整代纠错重试**把等待翻倍；全链路（worker 线程/registry/executor）**无任何任务级硬截止**。失败文案「查 Key/网络」是 `_job_failure_detail` 按**消息文本 substring** 分类落入 else 的误归因（Key/连通性实测正常）。

### P0 优化项清单
- **P0-1 结构化失败分类**：`LLMResponseError` 加 `code`（timeout/empty/parse/schema/quota/rate_limit/auth/http），文案按 code 分支——修掉归因错误并给前端分类按钮铺路（llm.py:98-108 + api/services/jobs.py:32-82）。
- **P0-2 per-role max_tokens 钳制**：`_ROLE_MAX_TOKENS`（diagnose 512/profiler 1024/gap 1024/eval 384/editor 3072…）替换 16384 全角色默认，length 翻倍上限角色化——直接砍输出 token→生成时延（P0-1 药方主体，与 PE 协同）。
- **P0-3 墙钟硬护栏**：单次 chat completion 外套可中断 deadline（超时 close 连接），让「30s」真成 30s——166s 类失败数学上不可达。
- **P0-4 条件性 transport 重试**：短输入角色（classifier/intake/profiler/gap）超时后 1 次重试，长生成（editor）维持不重试。
- **P0-5 结构化重试预算与降级**：max_retries=1 不放大 + 修复纠错重试丢失 `response_format`；gap 结构失败降级为空报告 + degraded 标记（profiler 维持硬失败）。
- **P0-6 成本护栏联动**：失败/重试按 attempts 记账 + 同任务连续失败 3 次熔断（`enforce_llm_task_entry` 前置拦截）。
- **P0-7 换备用节点重试接入点**：失败快照携带可用节点列表 + 新端点 `POST /api/jobs/{id}/retry-with-node`（activate + 重排队）。
